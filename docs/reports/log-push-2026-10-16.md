## 实施与验证计划

| 每目录 `ls -l` 和 `scp -r -p` 整目录 | 元数据列表由只读文件筛选取代；逐个 `scp -p` 普通日志、平铺落地；保持路径开始／结束、scp 成败 echo | 范围 3、6、8 |

脚本文本的写入／删除命令只在发给远端 SSH 的命令字符串中：`mkdir`、`rm`、`cat >`、`mv`；
master 本地只读目录、元数据、文件、hostname 和日期，变量／数组只驻内存。没有本地临时文件。
此结论针对 R1 整改后的代码；初始提交的 here-string 在 Bash 5.0 会创建临时文件，先前开发机快照检查未覆盖该问题，见下文。
没有增设 SSH 选项或改变应用用户的 SSH 配置。

## R1 整改与复验

[R1 台账](https://github.com/shenxg13/sql-apm/pull/66#issuecomment-6207513007)在
`fa2697b0392f45adf18dc61385bcb5d35fda9412` 发现 F-65-001：Bash 5.0 的 here-string 会创建本地临时文件，
创建失败时原代码继续发布空清单。此次改为关闭 glob 后直接按空白赋值数组；脚本不再包含 here-document／here-string。
自动检查拒绝重新引入这两类语法，并核对多目录、多天日志的完整传输、清单及源文件内容、mtime、权限不变。
成功日期按有界日期循环输出，不调用可能写临时文件的外部排序。

维护者通过[范围变更](https://github.com/shenxg13/sql-apm/issues/65#issuecomment-6207653317)及
[采用记录](https://github.com/shenxg13/sql-apm/issues/65#issuecomment-6207662845)纳入三项观察：

| 编号 | 修改与自动验证 |
| --- | --- |
| O-65-001 | 任一源路径不存在或不是目录，包含与有效路径混合且处于前／后的情况，均在 SSH/SCP 前非零退出，输出具体路径；存在的空目录仍成功且清单仅四行头。 |
| O-65-002 | 平台日期汇总按旧到新输出；单元测试核对三天顺序，真实 SSH 检查核对默认 7／3／24 天的日期集合和顺序。 |
| O-65-003 | 手册补全未知主机对应退出码 1；查找错误保留 `nested_filesystem` 或 `EACCES` 加错误说明。测试注入设备号差异和权限错误，核对返回 1、错误原因、受影响目录保留及其他可访问推送继续处理。 |

旧 Bash 取自 R1 已留存的 Kylin RPM：`bash-5.0-14.se.01.p04.ky10.x86_64.rpm`，
SHA-256 `43616d195aa7ede5ceacaadc9d8715d65307b7171f2641c037859c5a607e2c29`，实际版本 **5.0.17(1)-release**。
沿用提取目录的 wrapper（设置该 RPM 所需的 `LD_LIBRARY_PATH` 后 exec Bash）。
在私有 user/mount namespace 内把 `/tmp` 挂为只有根 inode 的 tmpfs，不改主机 `/tmp`。
测试夹具放仓库忽略目录，`TMPDIR` 明确指向隔离 `/tmp`；SSH/SCP 为本地替身，另用真实 SSH 链路验证。
复现方式（仓库根目录，需允许创建该命名空间）：

```bash
mkdir -p var/issue65/r1/fixtures
unshare --user --map-root-user --mount bash -c '
  set -e
  mount -t tmpfs -o size=1m,nr_inodes=1 tmpfs /tmp
  export TMPDIR=/tmp
  export SQL_APM_TEST_WORKDIR="$PWD/var/issue65/r1/fixtures"
  export SQL_APM_TEST_BASH="$PWD/var/issue65-review/r1/kylin-bash/wrapper/bash"
  "$SQL_APM_TEST_BASH" --version
  .venv/bin/python -m unittest discover -s tests -p test_log_push.py -v
'
```

实际探测 `/tmp` 空闲 inode 为 0，尝试创建文件得到 `ENOSPC`；以上 4 项测试全部通过。
多目录用例包含两个源目录、三天共 3 文件／60 字节；退出码 0，目标文件逐字节一致，清单恰含全部三条文件记录，日期输出有序。
完整输出保留于 `var/issue65/r1/bash50-fulltmp.log`。这是开发机运行提取的 Bash 二进制，不是目标 Kylin 系统或生产平台验收。

整改回归：收取测试 14 项、推送测试 4 项通过；`project_checks.sh` 的 131 项单元测试全部执行通过。
`verify_push.py --sshd-root var/issue54/sshd --timer` 通过，耗时 49.531 秒（含等待定时器）；
真实 SSH、PG 和用户定时链仍得到 29 日批／29 文件／145 记录与人工输入一致的结果。
日志分别保留在 `var/issue65/r1/project-checks.log`、`push-verification.log`；
完整 Harness 及 PR 在线契约检查的结果由 PR 整改记录保存，对应 `var/issue65/r1/harness-pr.log`。
