## 相对 v0.3.0 的变化

- 增加一次编译、按摘要复用的 Python 3.13.16、虚拟环境和 PostgreSQL 17.10 成品。
  二进制路径固定 `/data/sql-apm`，不安装编译依赖、不改变系统软件包；自检失败立即停止，由操作者选择编译路径。
- PostgreSQL 由 systemd 管理并开机自启，Grafana、指纹服务和每日运行服务在它之后启动；每日命令连接失败仍直接退出。
- postgres 系统账号可切换登录，裸 psql 使用本地 peer 超级用户；sfmon 裸 psql 使用 sql_apm，
  `psql -U sql_apm_ro` 使用只读账号，均无需重复输入密码。
- 数据库密码改为操作者输入两次，不回显、不随机生成。安装工具不叠加长度或字符规则，正确转义 pgpass 的冒号和反斜杠。
  空密码、换行或两次不一致会被拒绝。两个数据库账号接受任意非空单行密码；Grafana 的 admin、viewer
  保留上游至少 4 字符的限制，本项目不增加其他规则，也不修改固定组件绕过限制。
- 新增只面向生产的手册，旧手册用于演练验证。导入、构建、查询、四个看板及每日运行的数据行为不变。

**每日运行默认自动清理过期版本结果，并删除到期原始日志。** 默认结果保留 2 个月、原始文件 45 天；
分别用 `cleanup.enabled=false`、`raw_files.retention_days="off"` 关闭。

## 未验证

- 真实 APM 生产机的安装；生产安装时首先执行二进制自检，该机通过不是发版门槛。
- 从真实 MPP master 拉取日志，由用户上线时先手工拉一天核对。
- 120 三十天首批的成本；手册中的 32 GB PostgreSQL 参数建议值。

同类生产机只读预检（2026-10-12）：850 个已装包，对照离线 391 个 RPM，26 个未装、205 个相同、
160 个本机较旧、0 个较新，无版本冲突；按演练事务估计编译会升级约 31 个包。
它不是 APM 机器，不能外推兼容性或容量。历史资源数字及限定见生产手册。

## 不提供

本版不提供带数据升级的手册、脚本或演练；只支持全新安装，不能从 v0.3.0 原地升级。
后续版本将提供带数据的原地升级。本版不提供数据库备份和恢复，由部署方自行安排；
原始日志默认只保留 45 天，数据库损坏后更早的执行历史可能无法重建。
不覆盖其他操作系统、aarch64 或 `/data/sql-apm` 以外的二进制目录。项目许可证继续搁置。

## 编译路径和组件维护

编译路径会修改系统软件包：#52 演练实测新装 18、升级 28 个，包含 OpenSSL、util-linux、libstdc++、
krb5-libs、zlib、ncurses、e2fsprogs、perl；完整升级包清单在生产手册附录。
同类生产机内网源只有旧版本，编译升级后会偏离补丁基线，后续精确依赖旧版本的安装可能失败。

Grafana 13.2.3、Business Forms 6.3.5、Infinity 4.1.1、PostgreSQL 数据源 13.0.4 的固定摘要不变。
Grafana 13.2 系列官方支持截止 **2027-05-18**，见[官方支持表](https://grafana.com/docs/grafana/latest/upgrade-guide/when-to-upgrade/)
（2026-10-12 核对）。保持密码认证、插件签名和关闭启动自动下载；HTTPS 仍可选，默认 HTTP。
离线环境通过产品后续版本升级组件，v0.3.0 及更早标签和发布附件保持原样。
