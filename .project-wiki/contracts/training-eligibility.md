# 训练资格、黑名单与排除时段

## Summary

保存已确认的纳入规则及排除边界，未确认的新增黑名单条目仍由对应工作处理。
调整训练筛选、单条／整批单位、黑名单或排除时段时阅读。

## Contracts

### 已确认的 SQL 纳入与排除策略

- 确认日期：2026-09-22。
- 来源：用户提出采用黑名单策略，除明确排除的 SQL 外，其余都建立基线；随后
  引用控制语句、维护语句及具体 DDL 的讨论，确认“这些都可以列到黑名单里”。
- 来源状态：current；已确认 SQL 纳入原则和下列初始排除项，尚未实现过滤逻辑。
- 采用“默认纳入，明确排除”的原则：未命中黑名单的 SQL 进入基线计算范围。

| 类别 | 当前明确列入黑名单的语句 |
| --- | --- |
| 控制语句 | `SET`、`BEGIN`、`COMMIT` |
| 维护语句 | `VACUUM`、`ANALYZE` |
| 指定 DDL | `CREATE INDEX`（建索引）、`ALTER TABLE`（修改表结构） |

上述名单逐项列举；其他未明确排除的语句按默认纳入原则处理，包括此前讨论过的
`CREATE TABLE AS SELECT`。本次确认不扩展为排除全部 DDL。

黑名单控制是否参与基线计算。被排除语句仍可按执行关联需要用于上下文解析，
混合批次按下述已确认规则判定；日志及执行明细的存储与留存策略继续待定。
进入计算范围不等于已经具备可用基线；基本训练资格及暂定样本门槛见下述规则，
其余异常筛选策略另行确认。

具体配置方式与识别实现留待实施。首版语句类别名单的补充、别名／变体的
业务覆盖由下述 Issue #2 承接；具体 SQL 模板条目按已确认维护分工由用户
在后续生产运行中调整。

关联条款：[已确认的首期留存与自动清理边界](sql-storage.md#已确认的首期留存与自动清理边界)；[已确认的阶段与调用样本门槛](baseline-statistics.md#已确认的阶段与调用样本门槛)。

### 已确认的单条语句与多语句批次

- 确认日期：2026-09-23。
- 来源：用户对单条／批次分别建立基线及混合批次黑名单的完整提议，明确选择
  “采用上述规则，混合批次可建整体基线”。
- 来源状态：current；已确认训练单位、指纹粒度及黑名单应用原则，尚未实现。
- 单条 SQL 按单条生成结构指纹并建立基线。对于能可靠识别完整成功执行及整批
  耗时的多语句请求，保留语句顺序，对整个批次生成结构指纹，与单条 SQL 分开
  统计；不将整批耗时分配给各个子语句，也不借此生成子语句的独立耗时样本。
- 一次符合训练资格的整批执行计为一个有效执行样本，不按其中语句条数增加
  样本数；真实重复执行的同一批次仍逐次计数。基线继续按计算集群、数据库、
  执行用户及相应结构指纹分组。
- 纯黑名单语句组成的批次排除；包含未被黑名单排除的业务语句的混合批次，
  允许按整批进入候选集，其耗时包含控制和维护语句的贡献，不因首条为 SET
  就排除整批，也不从总时长中推测扣除黑名单语句耗时。
- 例如 `SET → BEGIN → INSERT → COMMIT` 或 `ALTER TABLE → ANALYZE → INSERT`
  在满足整批训练资格时可以纳入；只有 `SET → BEGIN → COMMIT` 的批次排除。
  原黑名单逐项定义保持不变，不扩展为排除全部 DDL。
- 状态不明、计时归属不清或执行关联不可靠的记录暂不训练。按整批纳入仍须
  应用既有的故障／维护时段排除及其他训练资格；混合批次许可不绕过这些规则。
- 对批次以选定完成记录的结束时间减整批 duration 推算批次开始时间，沿用
  北京时间的开始日期／小时归属和完整区间重叠排除，不声称恢复子语句起止时间。
- 完成记录选择、单条／整批计时映射及具体指纹规范化算法仍待落实。WHERE 条件及
  INSERT／UPDATE 业务值的处理，以及 SET 配置值和 LIMIT／OFFSET 数量的保留，见下述已确认
  规则；普通格式及注释差异的原则也已在下文确认，具体语法识别仍待实现。

关联条款：[已确认的基线分组维度](timing-and-grouping.md#已确认的基线分组维度)；[已确认的业务常量归一化](sql-fingerprints.md#已确认的业务常量归一化)；[已确认的执行配置与取数限制](sql-fingerprints.md#已确认的执行配置与取数限制)；[已确认的普通格式与注释处理](sql-fingerprints.md#已确认的普通格式与注释处理)；[已确认的时间口径](timing-and-grouping.md#已确认的时间口径)。

### 已确认的训练样本基本资格

- 确认日期：2026-09-22。
- 来源：用户对成功执行进入训练候选集、失败或不可靠执行不参与正常耗时训练的
  三类基本筛选原则回复“确认”。
- 来源状态：current；已确认训练资格原则，尚未实现状态判定、事件关联或样本筛选。
- 下列规则应用于未被 SQL 黑名单排除的执行。

| 执行情况 | 处理原则 |
| --- | --- |
| 成功完成，耗时完整，能可靠识别为一次执行 | 进入训练候选集 |
| 明确失败、取消或超时 | 不参与正常耗时基线训练 |
| 状态不明、耗时缺失或执行关联不可靠 | 暂不参与训练 |

进入候选集不等于最终用于训练。成功执行不能仅根据耗时长短直接认定为正常或异常。
故障与维护时段的人工排除、成功长耗时执行的处理见下述已确认规则；疑似离群及
高波动的自动标签已明确留待实际数据评估后确定，首期展示既有统计指标和样本
不足信息。具体异常判断方法另行确定，统计公式采用统计契约中的已确认定义。
训练窗口及暂定样本门槛见下述规则。
能可靠识别并归属到 SQL 分组的被排除执行，按下述已确认的执行历史范围
保留和展示；具体存储方式及保留期限继续另行讨论。

首期执行耗时及开始时间采用下述已确认的时间估算简化假设。完成记录的识别、
执行状态判定及其他必要的日志关联，留待结合日志格式与样本落实。

关联条款：[已确认的训练窗口](baseline-statistics.md#已确认的训练窗口)；[暂定的样本门槛与不足处理](baseline-statistics.md#暂定的样本门槛与不足处理)；[已确认的阶段与调用样本门槛](baseline-statistics.md#已确认的阶段与调用样本门槛)；[已确认的执行历史记录范围](../features/sql-search-and-views.md#已确认的执行历史记录范围)；[已确认的 SQL 原文存储方式](sql-storage.md#已确认的-sql-原文存储方式)；[已确认的首期留存与自动清理边界](sql-storage.md#已确认的首期留存与自动清理边界)；[已确认的首期执行时间估算假设](timing-and-grouping.md#已确认的首期执行时间估算假设)。

### 故障与维护时段的人工排除

- 确认日期：2026-09-22；2026-09-25 补充端点与零耗时样本的匹配规则。
- 来源：在询问首期是否需要手动指定“计算集群＋故障或维护时间段”，将受影响的
  执行样本排除出训练时，用户回答“需要”；随后对“SQL 执行区间与排除时段有
  重叠，就不参与训练”的匹配规则回复“确认”。
  对已生成基线因补录排除时段而重算的问题，用户明确表示“这个暂时不需要，
  因为sql日志是后录入的，不是实时采集”。2026-09-25，用户对排除时段采用
  “含开始、不含结束”、正耗时样本仅端点相接不排除、可靠零耗时按时间点
  判断的建议回复“确认”。
- 来源状态：current；这是已确认的首期功能范围，尚未实现操作入口或排除逻辑。
- 首期支持手动指定计算集群及故障或维护时间段，将该范围内受影响的执行样本
  排除出基线训练，避免已知故障或维护影响正常耗时基线。
- 这项排除也适用于已成功完成、原本符合基本训练资格的执行。
- 对指定计算集群，SQL 执行区间与排除时段有重叠即排除出训练；不要求 SQL 的
  开始和结束时间都落在排除时段内。
- 首期以完成记录的结束时间及下述方法推算的开始时间形成执行区间，保留其
  估算性质；不为该区间额外要求精确匹配开始日志。
- 因此，排除时段开始前已启动且期间仍在运行的 SQL、期间启动而结束于其后的
  SQL，以及完整跨越该时段的 SQL，均适用此规则。
- 例如排除时段为 10:00～10:30，执行区间为 09:50～10:10 的 SQL 也排除出训练。
- 首期按日志事后录入、离线构建基线的流程推进；在本轮构建前准备好日志及已知
  故障或维护排除时段，并在训练样本筛选时应用排除规则。
- 已生成基线因事后补录排除时段而触发的手动或自动重算流程暂缓，不列为首期
  必需功能。日常新增日志后的基线更新见下述已确认的更新与历史版本保留规则。
- 故障或维护时段按下述已确认的北京时间口径填写，采用“含开始、不含结束”
  的区间 `[排除开始, 排除结束)`。正耗时样本只有与该时段有正长度的时间重叠
  才因该时段排除：`样本开始 < 排除结束` 且 `样本结束 > 排除开始`。
- 恰好在排除开始时结束，或恰好在排除结束时开始的正耗时样本，不因该时段
  排除。例如排除时段为 10:00～10:30，09:50～10:00 和 10:30～10:40 不命中；
  09:50～10:01、10:20～10:40 命中。是否最终可训练仍按其他既定资格判断。
- 日志可靠记录为 0 ms 的样本按其时间点 `t` 判断：`排除开始 <= t < 排除结束`
  时排除；上述例子中 10:00 的零耗时样本命中，10:30 的不命中。不对零耗时
  样本套用正长度重叠条件而漏掉时段内的点样本，也不将未知耗时补为零。
- 边界判断沿用已确认的推算开始和日志结束时间，不把它们提升为精确实测开始
  或 activity 时间；各计时类别的样本单位及其他训练资格继续适用。排除时段
  已确认通过本地配置文件维护，具体格式、时间表示及匹配实现仍待落实，
  不因本条启动事后补录时段的追溯重算。

### 成功长耗时执行的处理

- 确认日期：2026-09-22（保留成功长耗时样本）；2026-09-25（自动质量标签后定）。
- 来源：针对通过基本筛选、未命中已确认排除规则的成功长耗时执行先保留参与
  统计，不仅因耗时长就自动剔除，疑似离群或高波动标记规则另行细化的建议，
  用户回复“确认”。2026-09-25，在询问首期是否先展示 CV、MAD、IQR 等统计值
  及样本不足信息、自动“高波动／疑似离群”标签和阈值待实际数据评估后确定时，
  用户选择“先展示指标，自动标签后定”。
- 来源状态：current；已确认首期样本处理及质量展示边界，筛选与展示尚未实现；
  自动质量标签留待后续工作。
- 成功完成、耗时完整且执行关联可靠的记录，在未命中 SQL 黑名单及故障或维护
  时段等已确认排除规则时，保留参与基线统计，即使其耗时明显长于同组其他执行。
- 首期不单凭耗时长或处于分布最慢端就自动剔除该执行。自动离群剔除算法留待
  后续结合实际数据分析确定，不将原始资料中的相关建议直接作为首期过滤规则。
- 首期保留并展示已确认的统计指标（包括 CV、MAD、IQR 等）及适用的样本不足
  信息，暂不自动生成“高波动／疑似离群”判断性标签。实际数据评估后，再确认
  是否引入自动标签及其具体方法和阈值；这不是首期实施的前置确认项。
- 既有样本数量与覆盖条件的达标／不足标记继续执行，已知训练排除原因继续
  保留。自动质量标签的延期不取消这些信息，也不把未产生标签解释为已经判定
  正常或稳定。标记本身不自动排除样本，成功长耗时执行沿用上述保留规则。
- 保留参与统计不等于已认定该次执行正常，也不代表其所在基线已具备异常判断
  的可用性。慢执行可能影响尾部统计，波动较大的分组仍需单独评估可用性，
  具体质量规则继续另行确认。
