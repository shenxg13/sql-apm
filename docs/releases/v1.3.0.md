## 相对 v1.2.0 的变化

- #73 第二批性能修复：执行记录派生层、检索、详情及时间范围排行提速；sqlfind 复用检索缓存；
  缺失计时身份的基线统计改为按完整键读取，避免扫描整个构建。
- 升级入口改为 v1.2.0 → v1.3.0：按事件数核算空间，事务内迁移及回填，保留配置、密码、
  sqlfind、每日运行单元与数据；连接错误输出简短 `STOP:`，不暴露原始 traceback。
- 沿用固定 Kylin 运行时：Python 3.13.16（含虚拟环境）、PostgreSQL 17.10，
  归档 SHA-256 为 `d271d6a1471c41723724b48afad59f9675e1b324747fbb7dfae283f97340314c`。
  不重新编译，Python 依赖、RPM、Grafana 与插件保持逐文件一致。
- 独立检查工具包 1.2.0 只支持本版／结构 1.14.0。修复工具自身事务语句引起的代表身份冲突，
  拆分模板绑定新源码，新增首次执行耗时与读取块数；公开字段白名单及严格脱敏检查同时生效。

## 已接受的资源成本与剩余差距

Issue #73 的开发机同批导入（含指纹）耗时增加 18.3%（measured）。新增结构持续占用模型为
20.064 GB（含 15% 余量），每天约增 0.803–0.812 GB（modeled），用户已接受。
升级停写模型为 22–61 分钟；额外工作盘模型约 100 GB，升级入口另计持续占用作为保守余量。

四类剩余差距仍保留：常见词检索、完整七天排行、常见词 sqlfind 初查加详情、十万份原文的目录显示。
这些项目已由用户接受，不把模型写成生产实测；生产复测仍逐项记录。
来源与测量边界见 [#73 验证报告](../reports/query-records-2026-11-03.md)。

## 已验证

Issue #73 已在开发机全量样本核对派生层一致性、查询结果和导入／构建行为；见上述报告。
本版两处带数据升级完成：64 张旧表和 11 类构建结果保持相同，8 项一致性重算均零差异；
验证机完成失败回滚、连接错误、failed 单元处理、17 项自检、三种检索、四看板及 sqlfind 检查。
验证机随后真实导入 5 个新文件并发布两个集群的新构建。两处工具包均完成全部用例三轮、首次读取、
计划和重点分析，通过脱敏打包；后台变量继承及看板复制权限问题已修正并验证。
详细身份、耗时、窗口及夹具边界见[升级验证报告](../reports/v130-upgrade-2026-11-03.md)。
实施方终端检查不代替用户 PuTTY 验收；用户确认后在发布前定稿中补入明确结果。

- 用户对照手册及 PuTTY 试用：须在正式独立评审前明确确认，当前不宣称完成。
- 真实安装上的完整 `resume` 未重新演练；目录恢复夹具及变化的复制步骤已在验证机补测，
  连接错误提示也经过实测。覆盖分别记入升级报告，不以自动回滚代替命令实测。

## 不提供

不备份数据库；迁移提交后不能回退到 v1.2.0。迁移失败由事务回滚，旧版本可继续使用；
提交后只能重装 v1.2.0，再从仍保留的原始日志重新导入和构建，需要数小时以上。
过期删除的原始日志无法重新导入。不支持从 v1.1.0 或更早版本直接升级。
不改变日志留存、结果清理或 PostgreSQL 参数；不包含运行中的 SQL、Docker 或许可证调整。
