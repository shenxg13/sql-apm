- 执行历史保留并展示所有能可靠识别为一次执行、并归属到该 SQL 分组的
  执行，包括成功、明确失败、取消、超时，以及因故障／维护等规则被排除
  出训练的执行；不因未参与训练就从执行历史中删除。

### 已确认的失败执行明细（2026-09-29）

- 来源：[Issue #18 的需求确认](https://github.com/shenxg13/sql-apm/issues/18)；来源状态 current。
- Master（`seg-1`）上每条带独立 SQL 字段（从 0 起第 24 列）的 ERROR 产生一条失败执行记录。
  解析／分析阶段即报错的请求也保留，不要求已经进入执行器。
- SQLSTATE `57014` 再结合消息：`canceling statement due to user request` 记为取消，
  `canceling statement due to statement timeout` 记为超时；其他 ERROR 记为失败。
- 这些记录结束时间取日志时间；耗时和推算开始未知，保存 NULL，不补零或推测耗时。
  能可靠生成结构指纹的可按 SQL 身份查看历史，只进历史，不参与训练。
- 不带 SQL 的 FATAL 等保留为批次问题，不构造 SQL 执行；解析器不支持语法不改变执行 outcome。
- #18 已实现上述明细入库；历史查询服务、展示、训练判定及基线分组构建仍由后续任务交付。

### 历史训练判定的复算边界（2026-09-29）

[Issue #21](https://github.com/shenxg13/sql-apm/issues/21)确认不逐条持久化每次构建的 Decision。
展示可通过快照、原文级结果和数据库函数取得当前支持规则的逐条结论；判定逻辑改版后，
旧快照只承诺已保存计数，不承诺逐条复算。历史页面须区分已保存计数与可复算明细，
不得以当前规则静默填充旧判定；本次仅更新展示约定，未实现界面。

### 未选入批次的历史判定（2026-10-04）

来源：[Issue #35](https://github.com/shenxg13/sql-apm/issues/35)。按窗口选批后，未选入批次
中未进入该版本快照的事件没有判定结果；展示时须标为“不在该版本输入范围内”，不能称为已经
该版本筛选或伪造 `outside_window`。选入批次中的窗口外事件仍可返回 `outside_window`。
执行历史直接读取保留的事件，不因是否选入而删除或隐藏；时间范围独立于训练窗口。
这是已确认的展示约定，查询界面仍待交付。

实现边界（2026-10-06，代码与合成验证）：既有去重允许同一文件被多个批次引用，
快照按选入批次的文件并集封存。因此事件是否在输入范围内须以 `input_file` 为准：
若另一选入批次包含该文件，其事件仍可返回判定，窗口外事件仍为 `outside_window`。
不能只看其中一个批次是否选入。此处说明既有去重与整批选入的组合行为，不新增展示功能。

### 检索与查询层（2026-10-07）

来源：[Issue #47](https://github.com/shenxg13/sql-apm/issues/47) 正文及需求确认评论；用户已确认，
命令和数据库函数已实现，真实验收与用户试用证据见本轮报告／在线 PR；Grafana 尚未交付。
这次确认取代此前“首期不增加片段检索”的边界，不改变导入、训练、统计、发布及清理规则。

- 模糊检索为主入口，精确检索同时保留。空白拆项，英文双引号括起的连续片段为一项；
  不成对的引号按普通字符处理，空输入与超过20项明确拒绝。各项均须匹配，位置和词序可不同。
- 比较只对 ASCII 字母转小写，删除空格、TAB、LF、CR、FF、VT；符号按字面，不作通配符或正则。
  无引号时各项可分散，有引号时去空白后的整段必须连续；用户接受去空白引起的偶尔多匹配。
- 原文按当前结构指纹归并；返回示例原文标识、匹配原文份数、记录数及涉及的集群／数据库／用户。
  默认记录数倒序，也可最近时间倒序，最多50个结构并返回总数。可选身份及时间筛选，计数随筛选变化；
  未筛选为全部保留范围。结果标为文本匹配，不将相似文本合并为正式基线。
- 完整指纹值输入直查命中列表。精确检索将整个 SQL／批次作为一个请求，复用当前安装规则；
  结果区分有基线、有记录无基线、未出现过、无法生成可靠指纹。最后一种给原因和可用的独立观察统计，
  明示观察结果不是正式基线。未出现过仍给指纹，输出包含规则上下文。
- 整体未命中的多语句请求追加前20条逐条提示并报告截断，提示不等于整批命中；不支持单条查所在批次，
  不转换非数据库语法占位符。原生 `$1` 与业务常量依既有规则归并。
- 每个命中身份一行，含是否存在当前基线、五类计时中哪些有数据、记录数和首末时间。
  选定集群、数据库、执行用户及指纹后不用重新输入 SQL。
- 默认基线摘要含当前版本信息及五类计时整体统计；17指标、有效样本数、活跃天数、排除计数／原因、
  基础／P95／P99门槛和不足原因均保留。没有样本仍给该计时并标为无样本；其余四层一次选一层。
- 只选已发布、尚未清理且规则相同的历史版本；不同规则的版本继续列出并标记，已清理返回明确错误。
  检索按当前规则，不更新指纹；历史查询给出未按当前规则生成结果的原文份数，非零时说明记录不完整。
- 执行历史六组为五类计时加未知计时；请求整体才代表完整执行，其余为阶段／调用且不加总。
  明细包含状态、结束／推算开始时间、耗时、单条／整批、来源文件／行号及原文标识；原文按需另取。
  未知计时耗时为NULL。默认100条，单次最多1000，可翻页；默认该身份最近记录往前7天，独立于训练窗口。
- 小时／天汇总分别给状态计数和已知耗时P50／P95／最大值；可附指定版本训练判定，文件未选入与旧规则
  不支持复算均明确表达，不以当前规则填补旧判定。
- 查询积木可以继续用普通SQL筛选、聚合；Python只负责指纹与命令适配。检索只读且不生成任务。
  函数参数、字段及示例由[开发说明](../../docs/design/sql-search.md)维护，后续变化须进发布说明。
- 本次性能目标为模糊10秒、精确3秒、摘要1秒、7天明细／汇总5秒，属于测量目标而非验收门禁。
  全量测量包含最坏和随机情况；本地120只有7天，生产30天且原文／明细累积，不能推定生产时延。
- 交付不包含Grafana、常驻Python服务、发版、Kylin实测及三份用户查询文档；开发说明与用户试用步骤随PR。
  用户自选SQL和关键词的试用确认是合并前要求，不能以自动化通过替代。

2026-10-08 实现修订依据为[维护者对 R1 的逐项决定](https://github.com/shenxg13/sql-apm/issues/47#issuecomment-6041514525)：
只给开始时间且晚于该身份最后一条记录时，明细与按小时／天汇总统一返回成功的空结果；
完整指纹值判断前删除首尾六类 ASCII 空白；长输入切分保持原有词法，不增加长度拒绝。
相邻引号片段仍拼成一项（例如 `"a"."b"` 得到 `a.b`、`"a",` 得到 `a,`），因此原样粘贴
带引号的 SQL 片段不保证找到同段原文。此限制本轮保持，后续 Grafana Issue 再确定交互与使用文档；
完整 SQL 可用精确检索。这是已确认的保留边界，不代表该限制已经消除。
