# SQL APM 使用性能检查

本工具包只适用于已经安装的产品 **v1.1.0／结构 1.12.0**。它检查使用过程的性能，
不修改产品，不改配置、不 reload、不重启、不重置统计，也不运行导入、构建和清理。
无需打开 Grafana 或手工操作 sqlfind。运行时指纹服务须已启动。

数据库查询逐条执行，没有并发测试。查询会读磁盘并占用缓存；请选择每日运行之外、无人使用的时段。
开始查询前会检查活动任务，发现正在运行则停止。执行期间不要另行启动每日运行。

## 准备工作

以下以 sfmon 登录操作。首次先准备父目录：

```bash
sudo install -d -o sfmon -g sfmon -m 0700 /data/performance-check
sudo setfacl -m u:postgres:rx /data/performance-check
```

这是一次性的目录准备；属主和属组为 sfmon，仅额外允许 postgres 遍历和读取父目录。
sfmon 通常无权在 `/data` 下直接建目录，所以这里使用 sudo；后续工具运行无需 root。
将工具包和独立交付的 SHA-256 文件放到 `/data/performance-check`。
不要解包到 `/data/sql-apm`。全部输出保存在本次工作目录；需要足够空间保存本地对照和查询记录。

```bash
cd /data/performance-check
sha256sum -c performance-toolkit.tar.gz.sha256
tar -xzf performance-toolkit.tar.gz
cd performance-toolkit
sha256sum -c SHA256SUMS
install -d -m 0700 /data/performance-check/run
setfacl -m u:postgres:rwx,d:u:postgres:rwx,d:u:sfmon:rwx /data/performance-check/run
setfacl -m u:postgres:rx /data/performance-check
```

核对交付记录中的压缩包摘要，再检查包内所有文件。ACL 只允许 sfmon 和 postgres 共享本次工作目录；
真实 SQL、检索输入、业务身份和重放语句会写入 `run/private`，该目录始终留在本机。
解包后的工具目录须允许 postgres 读取及遍历；工具目录自身不保存业务结果。

## 第一步：sfmon 运行主体

使用已有登录配置和密码文件。看板计时固定使用 sql_apm_ro；命令行读取原有账号配置，
工具额外强制只读，不更改账号的查询超时。若未显式设置 SQL_APM_DSN，命令连接使用同一只读连接及已有密码文件。所有产品 Python 模块以禁止字节码写入的方式运行。

```bash
cd /data/performance-check/performance-toolkit
./perfcheck main --work /data/performance-check/run
```

主体依次收集主机、规模、代表用例，然后测量看板、命令行及指纹服务。
每部分结束打印完成状态及秒数；计时部分还显示页面、命令、HTTP 操作及 SQL 数量、
超时、超参照和其他失败数量，以及各类最慢项的编号和毫秒数。操作与 SQL 分别计数，
同一操作的多条失败 SQL 不重复计算成多个失败操作。页面超参照表示至少一条 SQL 超过其参照；
其他操作按自身参照计数。超时单列，不重复计入其他失败；超时也可能同时超参照。
不命中命令的预期非零退出也计入失败，应结合逐项记录判断。
每部分终端摘要最多十行，每行不超过 80 个显示列。
采样每五秒读取 `/proc`，随计时开始和结束；
主机已用内存包含操作系统，进程 RSS 可能重复计算共享页，不是瞬时峰值。
读不到的项标为 unavailable。计时前后的数据库统计及增量在 `deltas.json`。

四个看板的 30 条面板 SQL、15 条变量 SQL 和 1 条 SQL 注释均被执行；6 个复用其他面板数据的 target 不重复查库。
图表间隔采用验证时 1920×920、收起导航的七天范围值 300000 毫秒；其他宽度下浏览器可能使用不同时间桶。
普通查询每项执行三次，保留第一次与后两次，不清缓存。单条达到只读账号原有超时即记录 timeout，
继续后续操作。2026-10-22 开发机全量样本实测普通计时含收尾 4354.249 秒（72 分 34 秒），
普通慢项计划另耗时 260.8 秒，第六节合计约 76 分 55 秒，超过一小时目标。
主要成本为命令实际查库，常见词交互流程的 27 次操作合计约 15 分 35 秒。
验证机部分样本对应普通计时 1683.1 秒、计划 49.9 秒，合计约 28 分 53 秒。
这些数值包含完整用例的三轮；两台机器各有九个去重后的代表身份，不能外推到生产。
完整证据与边界随验证报告交付，生产耗时取决于规模和超时数量。

如果可用时段不足，可先完成 host、inventory、cases，再从 `run/results/cases.json` 选择编号，
仅运行指定用例，编号参数可重复。每个所选用例仍执行三轮；结果明确标记部分覆盖，不能当作完整检查。
下面只测第一个用例，适合先估计本机成本；验证机独立轮次实测 137.698 秒，不能据此保证其他用例的耗时。
完整一轮仍使用前面的 main 命令。

```bash
./perfcheck timing --work /data/performance-check/run --case-id case-0001
```

同一部分重跑会替换其结果；若要同时保留完整轮次和减少用例的轮次，应分别准备工作目录。

### 代表用例与追加

每个集群从当前规则下可靠结构的完整执行记录选出六类身份：执行最多、原文最多的结构内执行最多、原文最长、
历史最多、最慢、执行最少。按指标排序，平局按指纹、库名、执行用户名排序；重复身份合并并保留类别。
没有可靠身份的类别明确记录原因。身份由集群、数据库、执行用户和结构指纹组成。
原文优先选该身份里字符数最长的一份，平局按 SQL 标识排序。

每份原文生成：前两个不同标识词、首个带引号片段（无引号则前 80 字符）、常见词 SELECT
（不存在则首词）、固定摘要组成的不命中输入，以及完整 SQL。覆盖按词、整段与完整 SQL 三种模式。
本地对照表保存真实值与稳定编号；结果包中只有编号、类别和数字。

选用例先对照固定导出名称：工具字段和固定文本、主机采样字段、PostgreSQL 统计列、设置名和编译字段、
计划字段以及目录中的表／索引／函数／模式名，并同时检查名称的 JSON 引号形式。
自动输入重名时按固定次序换候选：按词输入先前两词、再后续相邻两词、再单词；
常见词先 SELECT 或首词，再依原文词序；片段先各带引号片段、再前 80 字符、再完整原文；
不命中输入先摘要名、再带数字后缀的七个候选。完整原文不能替换内容。
任一类找不到安全输入，就继续同身份的下一份原文，再按同一类别排序尝试下一个身份。
各候选按八条一批读取，受每集群预算约束；重复身份仍合并。
`cases.json` 记录跳过的类别、候选序号和固定名称来源，绝不记录冲突值。
固定名称表采用保守匹配，可能跳过不实际导出的同源名称；打包自检及公共元数据白名单不变。

MPP 库名、执行用户名及手工追加输入由操作者决定，不能自动替换。
如与同一固定名称表冲突，cases 会在计时前停止，只报告类别和本地列表位置；
在本机查看 private 或追加文件确认，手工输入可改用更长、仍有代表性的检索片段。
业务库名／用户名冲突请保留本机证据并反馈维护者；不要改业务数据、删敏感值或绕过扫描。
已读取的外部身份和被拒绝的输入仍进入私有敏感值清单；打包已有部分结果也会继续扫描它们。
整改版应使用新工作目录，避免旧轮次敏感值及结果混入新选择。

选用例的独立会话预算默认每集群 600 秒，用 `--cases-limit-seconds` 调整为 1 至 3600 秒。
它覆盖该集群的候选聚合、原文回退和身份读取，不沿用只读账号的两分钟限制；
预算耗尽时该集群六类均标记 selection_timeout 并继续其他集群，部分选择不冒充完整。
目录及身份预检的每条查询同样使用这个上限；手工身份追加每条目另有同等预算。
选用例估时为集群数乘此预算，再加预检、追加及本地记录开销，并非总墙钟硬上限。
可先单独执行 cases 观察本机成本；普通 timing 始终使用账号原有超时，参数不影响它。

```bash
./perfcheck cases --work /data/performance-check/run --cases-limit-seconds 600
```

可在本机建立 JSON 数组文件追加查询，例如：

```json
[
  {"cluster": "本机实际集群", "mode": "words", "input": "日常检索词"},
  {"cluster": "本机实际集群", "database": "本机实际库名", "user": "本机实际用户名", "fingerprint": "本机完整结构指纹"}
]
```

```bash
./perfcheck main --work /data/performance-check/run \
  --extra-cases /data/performance-check/local-cases.json
```

该文件及其内容不会直接放入结果包。重跑代表用例会替换本次选择；数据不变时自动选择相同。

## 第二步：postgres 运行系统视图与计划

切换到 postgres 的登录终端，以本地 peer 连接运行。无需 root 权限。

```bash
cd /data/performance-check/performance-toolkit
./perfcheck system --work /data/performance-check/run
```

先读取累计健康指标、非默认及性能相关设置，再对普通计时中超过参照或一秒的语句取计划。
模块仅通过绝对路径 LOAD 到本次会话。版本、编译参数或模块摘要不一致时跳过取计划，并记录原因；
普通计时结果仍有效。NOTICE 只返回当前会话，服务器日志阈值在本会话设为 warning，计划不写入服务器日志。
计划中的表达式、常量和非允许文本替换为占位符，保留节点、表／索引、行数、循环、缓冲和耗时。

普通计划也使用 `--limit-seconds`，默认每条 600 秒，范围 1 至 3600 秒。
开始前打印实际去重的重放条数 N，最坏查询预算为 N × 上限秒数；连接和写结果另有开销。
慢项多时可能远超普通计时本身，可降低上限，例如仅重跑普通计划：

```bash
./perfcheck plans --work /data/performance-check/run --limit-seconds 60
```

### 重点分析列表与历史

普通慢项之后，逐个集群及“全部”运行：当前版本排行的 50、100、200、500 档，
时间范围排行和事件最多身份的历史面板的 24 小时、7 天、30 天档。
先对 v1.1.0 函数内语句做不执行的 EXPLAIN，再分别测量基线核心、前五行的 hits 查询、
数据库／用户变量和完整面板。各项实际执行一次，并单独记录计划及数字分布。

重点分析默认单条上限十分钟，可通过 `--limit-seconds` 指定 1 至 3600 秒；超时记录 over_limit。
它不包含在普通查询一小时的目标里。每个集群及“全部”最多 66 条计划／测量语句，
另有参数查询及四组分布查询；最坏预算随集群数线性增加。按每个范围最多 80 条（含查参数的语句）再加 32 条准备／分布查询保守计，
三个集群加“全部”在十分钟上限下最多 58 小时 40 分钟。
此为把每条均耗尽上限的保守语句预算，不是总墙钟时间的硬上限；连接、收集及结果写入还会增加时间。
本轮重点分析在开发机全量样本上为 78.446 秒、验证机部分样本上为 38.7 秒，
均为两个集群加“全部”；不代表三个集群的生产规模。具体证据随验证报告交付。

## 第三步：sfmon 打包并审阅

回到 sfmon 的登录终端：

```bash
cd /data/performance-check/performance-toolkit
./perfcheck pack --work /data/performance-check/run
cd /data/performance-check/run
sha256sum -c performance-results.tar.gz.sha256
install -d -m 0700 review
tar -xzf performance-results.tar.gz -C review
cd review
sha256sum -c SHA256SUMS
```

先读 `SUMMARY.txt` 开头不超过约 40 行的快速概要：部分状态、操作及 SQL 计数、
各类最慢几项与重点分析提示；计数与终端摘要共用实现，后面仍保留原有逐项明细。
概要同样经过敏感值扫描。再按 `FIELDS.json` 逐文件查看数值、编号、设置和计划，核对
`PUBLIC_METADATA.json` 中固定公共字段／设置名的白名单及适用位置。
确认没有真实 SQL、片段、检索词、业务库名／用户名、主机名／地址和密码后，只带出
`performance-results.tar.gz` 及其摘要文件。不要带出整个工作目录、private 或追加用例文件。
业务值和动态文本命中已知敏感值即拒绝打包，只指出文件名，不回显命中内容。
经核实的公共名称仅在声明的位置及对应清单、摘要引用中单独验收；同名业务值仍拒绝。
未列入白名单的重名也会拒绝，不得跳过自检，保留本机结果并反馈工具问题。

结果包用于公开报告前仍需用户审阅。自检只能发现已知敏感值，不能代替人工判断。
本轮不分析生产结果；后续分析和优化另立 Issue。

## 中断与部分重跑

按 Ctrl-C 取消当前查询并结束；已完成部分保留。不要删除正在运行的工作目录。
`*-state.json` 标出完成、失败或中断；部分结果不冒充完成。
可将入口的 main 换成 host、inventory、cases 或 timing，system 换成 plans 或 focus，
仅重跑对应部分。最终再次 pack。一个工作目录同时只允许一个进程运行。

版本不符时停止，不自动适配。连接失败时检查已有登录配置及密码文件；错误输出不包含连接串。
“每日任务进行中”时等待它完成，再重新开始。运行期间不要修改产品、看板定义或用例文件。

## 阅读参照

| 项目 | 参照及解释 |
| --- | --- |
| 模糊检索 | 10 秒，既有开发机测量目标 |
| 精确检索 | 3 秒，既有开发机测量目标 |
| 详情摘要 | 1 秒，既有开发机测量目标 |
| 七天明细／汇总 | 5 秒，既有开发机测量目标 |
| 页面估计 | 变量链合计加最慢面板，不含浏览器渲染及并行争用 |
| 统计增量 | 本轮计时前后之差；累计统计仍包含导入和构建 |
| 大小 | 表总大小已含索引和 TOAST，避免重复相加；与库总量的差额包括系统目录及其他对象 |
| 临时文件／顺序扫描 | 记录实际数值，结合执行计划判断；没有统一通过门槛 |

参照来源是产品既有检索测量目标；这些值均不是生产通过／不通过门槛。
采样单位：stat 为内核时钟 tick（只比较同机增量），meminfo 的数值为 KiB，vmstat 为内核计数，
diskstats 从读完成次数起保留内核原序的计数，负载为 1／5／15 分钟；进程 RSS 为 KiB。
只读账号无法读取的数据目录大小会在 postgres 的第二步补全。
主机采样、缓存、I/O、临时文件和节点行数用于后续分析；本工具不自动修改任何参数或索引。
