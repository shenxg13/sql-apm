# HashData 来源映射与证据边界

适用 profile：`hashdata-csv/1`。这是一份逻辑映射设计，不是解析器或配对准确率报告。
字段接收规则遵循[契约 C01–C07](../../../.project-wiki/contracts/offline-data-contract.md)
和[字段字典](fields.md)。未来来源或其他构建必须另核对 profile，不能只按同名字段套用。

## M01：CSV 记录与字段定位

CSV 引号内换行属于同一逻辑记录。`record_no` 从 1 开始，`line_start/end` 为物理行闭区间；
`observed` 键为下表两位序号。源文件为不可变字节，摘要和定位可回放；
首期参考编码 UTF-8，无效字节不丢弃、不替换后冒充原文，也不擅自改为其他编码。
列数／记录边界不可靠时以文件级失败表达；能隔离的单个字段问题保留在记录／批次诊断。

| 序号 | 观察含义 | 逻辑去向与限制 |
| --- | --- | --- |
| 00 | 日志时间 | 选定计时／终止记录的 Occurrence.end_at；原始文本仍在 observed |
| 01 | 执行用户 | execution_user，非空且可靠才用于 Group |
| 02 | 数据库 | database，非空且可靠才用于 Group |
| 03 | 进程标识 | 关联线索，不单独作为全局会话／执行 ID |
| 04 | 线程标识 | 关联辅助证据；不新增分组 |
| 05 | 客户端地址 | 辅助证据，不能由它确定集群 |
| 06 | 客户端端口 | 辅助证据，不是执行键 |
| 07 | 会话开始时间 | 会话身份辅助；与 duration 推算开始不同 |
| 08 | 事务线索 | 保留文本，不假定单次调用唯一性 |
| 09 | 会话标识 | 联合来源、会话起点及其他证据解释，不跨 Master 硬匹配 |
| 10 | 命令计数 | 关联辅助；已有案例在相关阶段间变化 |
| 11 | 节点标识 | 已调查样本 seg-1，不能由此证明是完整业务执行 |
| 12 | slice 线索 | 原始辅助上下文 |
| 13 | 分布式事务线索 | 原始辅助上下文 |
| 14 | 本地事务线索 | 原始辅助上下文 |
| 15 | 子事务线索 | 原始辅助上下文 |
| 16 | 日志级别 | outcome 证据之一，不与导入状态共用 |
| 17 | SQLSTATE | outcome 证据之一，不能仅凭 00000 推定一次完整成功执行 |
| 18 | 日志消息 | duration 数值及 execute/fetch、parse/bind 文本线索 |
| 19 | DETAIL | 错误／参数上下文；不恢复绑定实参，不自动作为完整 SQL |
| 20 | HINT | 保留诊断线索，不等于 SQL 中执行 Hint 注释 |
| 21 | 内部查询文本 | 诊断线索，不能替代外层业务 SQL 或新增外层执行 |
| 22 | 内部查询位置 | 内部错误定位，可为空 |
| 23 | 上下文 | 诊断线索，可能包含敏感内容，公开材料不复制 |
| 24 | 独立 SQL 文本 | 选定记录的源 SQL 候选；非空并不证明完整 |
| 25 | SQL 位置 | 诊断定位，不当成语句数 |
| 26 | 函数名 | 调查中计时记录该列为空；不能把源码推断的函数名伪写为观察值 |
| 27 | 源码文件 | 与 28、源端构建共同解释计时；不是日志文件路径 |
| 28 | 源码行号 | 本构建识别证据，非通用协议编码 |
| 29 | 堆栈 | 原始诊断上下文，不参与分组 |

没有出现在 CSV 中的 cluster_id／source_id 来自人工 Source 映射；
file_id、校验摘要、记录序号、物理行和导入时间来自导入过程；
estimated_start_at、计时类别、关联可靠性、结构指纹、训练资格及统计都是派生解释。

## M02：五类计时映射

| 当前构建的来源 | 取值／配对依据 | 结果及单位 |
| --- | --- | --- |
| postgres.c:1946 | 00 结束、18 duration、24 SQL；确认正常请求边界及影响范围 | request，一次单条／完整批次请求 |
| postgres.c:2843 + :2764 的 execute | 2843 提供结束、duration、独立 SQL；2764 可靠识别同次首次调用 | execute_first，一次调用，不证明完整取数结束 |
| postgres.c:2843 + :2764 的 execute fetch from | 同上，2764 提供续取类型 | execute_fetch，一次续取 |
| postgres.c:2219／:2224 | 同一 Parse 阶段的简略／详细输出；可靠 SQL 和阶段归属 | parse，一次阶段调用 |
| postgres.c:2603／:2608 | 同一 Bind 阶段的简略／详细输出；可靠 SQL 和阶段归属 | bind，一次阶段调用 |
| 2843 未可靠配对 | 保留已知计时与 SQL；timing_reason 说明不确定原因 | timing_type=null，保留诊断，不进入五类 |
| postgres.c:1455、autostats.c:334 等范围外位置 | 保留来源、数量与已知原因 | 不纳入五类；不构造 request 样本 |

同类简略与详细分支都进入其类别候选，不是将两阶段相加；不能仅看 message 是否有
`execute` 或是否超过一分钟判断阶段。明细事件、词法候选及日志条数的单位必须分开。
未知构建恰好有相同行号不构成可靠映射。

## M03：时间、耗时和 SQL

`duration: 数值 ms` 提供十进制毫秒，保留原精度。无此值、负值、格式非法或不可靠时
不生成有效 duration，原始消息留存并记录原因。0 ms 表示日志值为零，不证明真实耗时精确为零。
00 先按来源已确认时区解释；没有明确时区的输入不得猜测 CST 含义。
选定完成记录的时间与可靠 duration 推算本次事件开始，归入北京时间日期／周／星期／小时。
不把 2764 时间直接替代推算开始，也不把会话开始当成 SQL 开始。

SQL 优先使用选定计时记录的 24 列，如已调查 2843；简略 message 只有 duration 不代表
整条 CSV 没 SQL。详细 Parse／Bind message 内 SQL 可作为有依据的文本来源，必须记录
列号、包络提取规则及与 24 的核对结果；冲突不静默选一份。能否可靠采用替代字段属于
Analysis 的明示规则，不能从任意邻近 message、DETAIL 或内部查询补齐缺失业务原文。
本版本样例使用 24；无法核实完整性时保留 sql_state=uncertain，不创建正常训练分组。

不得仅靠“文本非空”“长度 1023 字节”“词法闭合”分别推出完整／截断／SQL 有效结论。
存在明确截断、非法编码、缺失或不支持语法时，区分源文本问题与解析能力不足。
未能解析整个批次不能抽取其一部分并使用整批 duration。函数未知但按既定规则保留，
与结构无法识别是两件事；Fingerprint 失败不回退 SqlText 身份或原文哈希训练。

## M04：关联和结果状态

可靠单次 Execute 配对至少需要同逻辑来源、可核实会话身份、记录顺序以及
SQL／上下文一致性的依据；记录具体 evidence_refs 和 association_version。
文件边界本身不必切断会话，但跨文件关联仍须明确顺序和来源，存在冲突或缺口就报告不确定。
同 SQL、同命令号或时间最近均不是充分条件。成功配对不证明 portal 生命周期完整。

outcome 以该请求／调用的完整证据集合判断；与它可靠关联的 ERROR、取消或超时证据
可以给出相应状态，否则保留 unknown。本设计不规定错误归因算法，也不把 SQLSTATE
单列或 LOG/00000 当作完整成功证明。明确业务执行失败可以是导入成功的记录，
“解析器不支持 SQL”不能被标为 execution_failed。

无法可靠识别事件边界时只产生批次 Problem；已知一次调用但首次／续取未知时
可以保留 Occurrence，分类为空，并在批次层诊断，不能作为第六类训练分布。
