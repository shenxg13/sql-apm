# SQL 检索、Grafana 与历史展示

## Summary

### 已确认的首期统一入口展示范围

- 确认日期：2026-09-24。
- 来源：用户偏好将 Grafana 作为统一入口，并在询问首期入口范围时选择
  “先覆盖 SQL 检索、基线和执行历史展示”，随后明确回复
  “确认将 grafana 插件作为主要候选”。用户进一步要求 Business Forms 与
  自定义 App 插件均保留为候选，选择维护简单的，并表示 Business Forms
  可能更合适。
- 来源状态：current；已确认展示范围和主要候选方向，界面及检索服务尚未实现。
- 首期通过统一入口进行 SQL 检索、查看相关基线和执行历史；以 Grafana
  插件作为该入口的主要实现候选。具体插件尚未选定，候选方向的确认不等于
  已完成兼容性或交互验证。
- 本次确认不增加导入、构建、黑名单和排除时段的网页管理要求；已有导入、
  构建及人工排除能力的需求继续有效，操作采用上述已确认的命令行与本地配置
  文件方式，具体实现仍待落实。
- Business Forms 与自定义 Grafana App 插件均为候选；在满足首期功能的
  前提下，以维护简单为选型优先条件。用户倾向 Business Forms，后续优先
  评估其适配程度，同时保留自定义 App 插件方案。该倾向不表示已经选定
  Business Forms，也不表示其在本项目中的维护成本已经验证更低。
- Appsmith 保留为未选定的替代方案。检索与分组选择采用下述已确认规则；
  指纹算法细节、具体接口、插件兼容性和面板交互仍待落实。
- 展示需求不改变 SQL 原文、逐次执行明细及历史版本留存策略的待定状态。

### 已确认的 SQL 检索与分组选择

- 确认日期：2026-09-24。
- 来源：用户对“允许直接粘贴完整 SQL 或完整批次，复用入库归一化规则
  按结构指纹检索；集群、数据库和执行用户作为可选筛选，多分组分别列出
  供选择”的建议回复“确认”。
- 来源状态：current；已确认首期检索行为，尚未实现检索接口或界面。
- 输入完整 SQL 或完整批次，复用日志入库时的归一化规则生成结构指纹，
  查找对应的基线分组；沿用已确认的业务常量、特殊值、格式、注释及单条／
  整批处理边界，不另设一套仅用于界面的归一化规则。
- 计算集群、数据库及执行用户均为可选筛选条件，允许先输入 SQL 再查找
  相关分组，不要求预先选齐三项条件。
- 命中多个分组时分别列出供用户选择，选定后查看该组的基线与执行历史。
  仍按计算集群、数据库、执行用户及 SQL 结构指纹区分分组，不自动合并
  不同集群、数据库或用户的统计与执行历史。
- 具体控件、接口及指纹算法仍待落实；SQL 原文按上述另行确认的精确去重及
  明细引用方式保存，具体留存期限仍待定。原文入库不自动增加原文精确匹配
  或 SQL 片段检索能力，首期检索仍按已确认的结构指纹规则进行。

关联条款：[已确认的业务常量归一化](../contracts/sql-fingerprints.md#已确认的业务常量归一化)；[已确认的原生参数与业务常量归并](../contracts/sql-fingerprints.md#已确认的原生参数与业务常量归并)；[已确认的 SQL 原文存储方式](../contracts/sql-storage.md#已确认的-sql-原文存储方式)；[已确认的首期留存与自动清理边界](../contracts/sql-storage.md#已确认的首期留存与自动清理边界)。

### 已确认的基线版本与执行历史查看

- 确认日期：2026-09-24。
- 来源：用户对“默认展示当前生效基线，支持切换已保留的历史版本，标明
  训练窗口、构建时间和样本不足状态；执行历史时间范围独立选择，查看操作
  不重算基线或切换系统生效版本”的建议回复“确认”。
- 来源状态：current；已确认首期查看行为，尚未实现页面或查询接口。
- SQL 详情页默认展示当前生效的基线版本，支持手动选择已保留的历史版本；
  沿用已确认的发布规则，不将尚未生效的最近构建结果当作当前生效基线。
- 展示所选版本的训练窗口、构建时间和样本不足状态；分组与指标的不足标记
  沿用已有规则，不因展示或选择历史版本而改变。
- 执行历史的查询时间范围独立选择，调整它仅改变历史记录的展示范围，
  不触发基线重建，也不重算或替换所选版本已经保存的统计结果。
  例如，查看最近 7 天的执行曲线时，仍可使用由 30 天样本构建的所选基线
  作为参照；基线训练窗口不随执行历史的查看范围缩短。
- 查看历史基线版本仅改变页面展示，不改变系统当前生效的基线版本。
- 本次不确定执行明细及历史基线的保留期限；具体控件与查询接口仍待落实。

关联条款：[已确认的基线更新与历史版本保留](baseline-versions.md#已确认的基线更新与历史版本保留)；[已确认的首期留存与自动清理边界](../contracts/sql-storage.md#已确认的首期留存与自动清理边界)。

### 已确认的执行历史记录范围

- 确认日期：2026-09-24。
- 来源：用户在执行历史范围问题中明确选择“展示全部可可靠归属的执行”。
- 来源状态：current；已确认保留及展示范围，尚未实现执行明细存储或界面。
- 执行历史保留并展示所有能可靠识别为一次执行、并归属到该 SQL 分组的
  执行，包括成功、明确失败、取消、超时，以及因故障／维护等规则被排除
  出训练的执行；不因未参与训练就从执行历史中删除。
- 展示执行状态及已知的训练排除原因。耗时缺失或不可靠时显示“未知”，
  不补成零，也不伪造完整执行耗时。
- 历史展示不改变既有训练资格：明确失败、取消、超时，以及状态或耗时
  不满足可靠性要求的执行仍不参与正常耗时训练；其他已确认排除规则继续适用。
- 展示单位沿用单条 SQL／完整批次的执行粒度，真实重复执行分别保留；
  不将 Parse／Bind 阶段日志或一条批次内的子语句另算为独立执行。
- 无法可靠识别执行或归属到 SQL 分组的日志问题，仍在导入批次层面查看，
  不强行归入具体 SQL 的执行历史。
- 本次确认记录类别的保留及展示范围；对应可靠 SQL 原文采用上述另行确认的
  精确去重保存及明细引用方式，具体保留期限、字段映射和界面实现仍待落实。

关联条款：[已确认的训练样本基本资格](../contracts/training-eligibility.md#已确认的训练样本基本资格)；[已确认的五类计时统计与 Parse／Bind 纳入](../contracts/timing-and-grouping.md#已确认的五类计时统计与-parsebind-纳入)；[已确认的 SQL 原文存储方式](../contracts/sql-storage.md#已确认的-sql-原文存储方式)；[已确认的首期留存与自动清理边界](../contracts/sql-storage.md#已确认的首期留存与自动清理边界)。

### 已确认的 activity 基线参照选择

- 确认日期：2026-09-23。
- 来源：用户对“开始小时优先，不足时回退整体；两者都不足时展示已运行时长
  及基线不足，暂不自动判断异常”的建议回复“确认”。
- 来源状态：current；已确认后续 activity 比对的参照选择原则，尚未实现采集、
  匹配或异常判断，不因此把 activity 采集实现纳入当前需求记录工作。
- 匹配范围仍限定在相同计算集群、数据库、执行用户和 SQL 结构指纹的基线分组。
  以待比较 SQL 执行的开始时间所属北京时间小时选择对应的跨天小时画像。
- 开始小时对应的画像可用时，优先使用该小时画像作为比较依据。
- 该小时画像不足、同组整体基线可用时，回退整体基线，并明确标注参照来源。
- 小时画像和同组整体基线都不足时，展示已运行时长及“基线不足”，暂不自动
  判断异常；统计依据不足不能当作已判定执行正常。
- “可用”需满足所用指标的样本门槛及后续确定的质量条件，不能仅因保存了
  统计值就认定可用；P95、P99 沿用各自已确认的样本条件。
- 本次确定优先与不足回退原则。邻近时段的额外参考、activity 字段与 SQL
  指纹的具体匹配、异常判定公式及多指标组合方式继续待确认。

关联条款：[已确认的基线分组维度](../contracts/timing-and-grouping.md#已确认的基线分组维度)；[暂定的样本门槛与不足处理](../contracts/baseline-statistics.md#暂定的样本门槛与不足处理)；[跨天小时画像的独立样本门槛](../contracts/baseline-statistics.md#跨天小时画像的独立样本门槛)；[已确认的阶段与调用样本门槛](../contracts/baseline-statistics.md#已确认的阶段与调用样本门槛)。
