## 制品、环境与执行边界

候选程序提交 `151dfcb61ed1105c776b940734e3aed457814e96`，`v0.1.0` 预发布。
精简程序 SHA-256 为 `ef5efb1de9cd59272271902d809fae8ff02f61fdac2478816f80e84daedf176a`；
内网完整离线包 SHA-256 为 `373a943321075d46450c8d14ec158997c1ccfc3f830c33574328d55deb9c7b94`。
本轮使用准备报告记录的原候选包，没有因试跑重新生成或替换产品文件。

观察（observed）：Kylin V10 SP2 Build09、glibc 2.28、8 vCPU、约 14 GiB 内存，
`/data` 为 190 GiB XFS；初始项目目录不存在，没有 PostgreSQL 用户或实例，只有 SSH 监听。
快照恢复及底层迁移 SSD 来自用户确认（user-reported）。来宾系统仍将 VMware 虚拟盘
报告为 `ROTA=1`，这个虚拟设备标志不能独立证明宿主机的物理介质。

源码、wheel、RPM 和源日志均复用此前保留且核对过的材料。
手册命令按阶段保存到本地忽略目录，再通过 SSH 执行；命令中的目标地址和允许网段
来自已授权交接。Python 和 PostgreSQL 在不同构建目录各以 `make -j4` 并行编译；
传输、编译和三组自检均在业务试跑前结束。
性能采样只读取 `/proc` 计数，不添加磁盘压测或修改产品默认并发、5 秒解析期限和数据库参数。

### 失败现场与单进程复跑

确认无运行任务、无其他客户端后正常停库，将失败 PGDATA、记录、凭据、配置和 socket
分别保留在项目内的 `*-ssd-workers4` 目录。记录压缩包已备份到开发机，
SHA-256 为 `32676548ec2245ca705b38e58b03cec41ba4bf7178eab5de234e43b093630cec`。
新建干净实例，bootstrap/schema/check、正确／错误密码 TCP 验证再次通过，
重新生成配置后用 `--workers 1` 运行同一首批，最终通过：26 文件、5,124,686 条记录、
2,547,876 次执行，归一化超时为 0；正式分组 51,266、正式统计行 509,766、
观察统计行 164，全部 Alma 比较和版本链核对一致。四进程失败的 7 个文件在单进程下
全部零超时；没有修改产品代码、默认四进程或 5 秒期限。

单进程全流程及核对耗时 2,674.911 秒，结束时数据库 12,444,464,819 字节，
文件系统已用 50,054,676,480 字节、可用 153,856,655,360 字节。
文件系统占用包括保留的失败数据库、源日志和安装材料，不等于当前项目数据库大小。
最终查询只有 1 个成功任务、119 的 1 个发布版本及 26 次成功导入，没有运行中或中断任务。
当前项目数据库保留这个通过验证的单进程首批，供后续查看。

### 四进程与原机械盘同一首批的运行对比

| 阶段 | 机械盘四进程（秒） | SSD 四进程（秒） |
| --- | ---: | ---: |
| 导入 | 1,855.321 | 1,824.886 |
| 快照 | 108.450 | 54.957 |
| 统计构建 | 469.495 | 201.436 |
| 检查 | 2.162 | 2.056 |
| 发布 | 0.003 | 0.005 |
| 全流程及核对 | 2,436.168 | 2,083.681 |

两次都是同一 119 首批和相同产品文件。总耗时从约 40.6 分钟降至 34.7 分钟，减少 14.47%；
导入阶段仅减少 1.64%，改善主要在快照和统计构建。两次四进程均有超时和不完整分组，
分别为 891／882 次超时、51,143／51,152 个正式分组，不能把较快完成等同于正确完成。

本轮四进程全程采样 2,083.726 秒：CPU I/O 等待 0.067%、数据盘忙碌率 3.22%，
平均读取延迟 0.614 毫秒、平均写入延迟 0.249 毫秒。5 秒间隔的多段采样观察到约
四核计算、磁盘几乎空闲，超时仍发生。此前机械盘 20.098 秒导入样本的读取延迟为
41.842 毫秒、忙碌率 93.54%、I/O 等待 10.71%，但它来自 120 日批且采样长度不同；
不能据此计算本次首批的严格磁盘加速倍数。旧迁移对照的边界详见
[原报告](kylin-offline-deployment-2026-10-02.md#ssd-恢复与性能对比)。

观察支持本轮 SSD 环境的磁盘等待较低，但不支持“换 SSD 即消除四进程超时”。
完整根因仍待后续定位；缓存、宿主机调度和其他负载未严格控制，以上是运行对比而非硬件基准测试。
单进程全程采样的 I/O 等待为 0.036%、磁盘忙碌率 2.477%、平均读取延迟 0.514 毫秒；
完整汇总与两轮每 5 秒原始采样分别保存在机器记录和本地证据中。
