## 相对 v1.1.0 的变化

- #72 第一批性能修复：当前基线排行先限量再读覆盖信息；详情训练标记按完整键定位；
  名称下拉框和缺失指纹计数使用精确汇总，导入和训练事务同步维护。
- 新增原地升级入口，检查旧版、运行时、任务和空间，停止写入方后单事务迁移，
  保留配置、密码、sqlfind 和每日运行单元，更新程序及随包看板。
- 沿用 v1.0.0／v1.1.0 的唯一 Kylin 运行时：Python 3.13.16（含虚拟环境）、PostgreSQL 17.10，
  归档 SHA-256 为 `d271d6a1471c41723724b48afad59f9675e1b324747fbb7dfae283f97340314c`。
  Python 依赖、RPM、Grafana 和插件保持相同，不重新编译。
- 独立性能检查工具包更新为 1.1.0，支持本版与结构 1.13.0，重点分析保留来源绑定并测量各排序的排行函数。

## 已验证

Issue #72 在开发机全量样本验证了 4,101 个案例、442,737 行输出和既有表摘要相同，
以及导入、构建和迁移结果；这是已合并修复的证据，见[性能验证报告](../reports/query-performance-2026-10-26.md)。
本版开发机全量样本、验证机部分样本均已从正式 v1.1.0 升级，迁移分别为 9.56 秒和 4.58 秒。
旧数据与构建结果保留；验证机还通过了真实迁移失败回滚、17 项随包自检、四个看板、三种检索及原连接配置的 sqlfind。
固定运行时与第三方组件不变，同一候选的程序、验收、完整离线包及工具包重复构建字节相同。
详细环境边界、尚待完成的每日运行和性能复测见[升级验证报告](../reports/v120-upgrade-2026-10-27.md)。

## 不提供

本版不备份数据库，不提供迁移提交后回退到 v1.1.0 的手段。
迁移失败由事务回滚；提交后只能重装旧版并从仍保留的原始日志重新导入和构建，需要数小时。
已有日志留存、结果清理和 PostgreSQL 参数不变；不包含运行中的 SQL、Docker 或项目许可证调整。
