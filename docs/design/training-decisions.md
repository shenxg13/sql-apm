# 训练样本判定设计

[Issue #21](https://github.com/shenxg13/sql-apm/issues/21) 已确认 D1–D9 及方案 C，
本设计细化其实施选择。② 固定输入和配置、缓存原文规则结果、按需推导资格；
③ 统计与 ④ 构建／发布另行实施。

## 实施顺序与验证计划

1. 在结构 1.2.0 上启动已授权的 55 文件私有重导；输入保留 SHA-256，导入语义不变。
2. 新增产品类别识别、本地 JSON 配置和原文规则缓存；用七类别、暂缓别名、混合批次、
   模板结构匹配及限定范围的正反例验证。
3. 在 1.3.0 复用快照及关联表，以已完成批次、成功文件和唯一选定 Analysis 的清单固定输入。
   配置保存完整规则及来源声明；数据库拒绝修改已封存的快照和缓存。
4. 用一套数据库函数推导状态、全部原因、八项评估、分组及计数范围。诊断汇总复用该函数。
   测试未知条件、多原因、五类计时、窗口、半开时段和零耗时边界。
5. 验证新建、1.2.0 升级、从 1.0.0 连续升级和同版重跑；旧数据及旧结构校验保持。
6. 完成真实输入快照、全量汇总、重复推导和 #18 对账；记录实测耗时；同步知识及命令说明。

## 成本、并发与恢复

- 原文级结果按原文与规则身份唯一，跨快照复用。更换模板或归一化上下文生成新身份，旧结果保留。
- 全量扫描和重导是 D7 的明确验收成本，目的是验证真实输入守恒和推导性能；
  使用既有导入流程和私有临时实例，原始 SQL 与身份不出现在报告。
- 常规诊断按快照查询，不重复解析每条执行。首次缓存成本与去重原文量成正比；
  全量推导成本与快照事件量成正比。耗时在验收后以 measured 记录，不预先宣称达标。
- 缓存按有界批次提交，中断后复用已提交结果；快照在一个事务中完整封存。
  使用规则级缓存锁避免同原文／规则并发重复计算；不实现④的任务编排和集群串行调度。
- 不永久保存逐条 Decision；必要时诊断使用会话内临时结果。持久快照与规则保留，
  判定规则改版后旧快照不承诺逐条复算，已保存汇总仍可解释。

## 物理接口

- 类别以完整语法为前提；类别版本 `statement-categories/3` 在词法标签上归并已确认的
  `END` → `COMMIT`、`START TRANSACTION` → `BEGIN`、`ANALYSE` → `ANALYZE`，再判断整批类别。
  可靠指纹快速路径与完整解析路径共用归并；共享词法器仍保留原拼写。
  SET 另核对解析后的参数名，沿用 v2 对带引号身份参数、事务特征参数和带前缀的
  `SESSION CHARACTERISTICS` 的暂缓处理，普通带引号参数仍可命中。
  [确认边界](../../.project-wiki/contracts/training-eligibility.md#事务特征设置的补充确认2026-09-30)
  与诊断词法标签分开维护；规则变化生成新规则身份及缓存，旧快照继续引用原缓存。
  [Issue #23 别名边界](../../.project-wiki/contracts/training-eligibility.md#三个纯别名的补充确认2026-09-30)
  不改变七类名单、原因码、判定版本或数据库函数。
- `mpp_training_rule` 固定类别完整边界、模板原文与结构指纹、完整归一化规则／字典快照。
  `rule_id` 是上述规范内容的 SHA-256 身份。`mpp_training_sql` 按 `(sql_id, rule_id)`
  保存一次类别结论、类别集合、模板候选 ID 及 Fingerprint 引用；范围限定在逐条推导时应用。
- `input_file_analysis` 为每个成功文件固定唯一 Analysis；`input_manifest` 保存去重文件摘要、
  批次、日期、解释版本和来源映射。输入集合是这些文件内、所选 Analysis 下的事件，
  没有逐条事件清单；后续给同一 Analysis 增加其他文件不会进入旧快照。
- `training_config` 补充配置的判定版本与完整来源声明。配置引用的规则内容保存在
  `mpp_training_rule`，既有 `config_snapshot` 仍保存窗口、黑名单、时段和五层默认门槛。
- 快照事务先插入关联成员，最后用 manifest／training_config 封存。触发器拒绝封存后
  对父记录和成员的插入、更新、删除；原文规则缓存也拒绝更新、删除。普通 owner 模型下
  不防护主动删除约束／触发器的管理员操作，结构检查会识别这种漂移。
- `mpp_training_decisions(input_id, config_id, analysis_id DEFAULT NULL, occurrence_id DEFAULT NULL)`
  是唯一的资格实现。函数以解析后的 SQL 体绑定表，支持自定义 schema。只读函数不创建
  Build、Statistic 或永久 Decision 行。单条查询传入后两个参数，批量统计省略它们。
- 返回四种状态、全部原因码和规则引用／锚点证据、八项评估、计时类别、推算开始／耗时、
  类别及命中的模板／时段 ID。`outside_window` 优先，但保留全部已知原因；明确失败或
  黑名单／时段命中为 excluded，其他可靠性不足为 unresolved。
- Group 在②中是按五项键和规则上下文计算的逻辑投影，`group_id` 为不透明摘要，
  不要求在 `mpp_baseline_group` 写入每个观察组。③可以按该身份保存需要的 Group。
  不可靠关联／身份／计时／指纹不能产生 Group；已知组且开始可归属为 `count_scope=group`，
  其余为 batch，窗口外为 none。汇总的 null reason 行是去重总量，各具体 reason 行独立计数，
  原因之和可大于总量；窗口外原因单列，不冒充窗口内排除。
- `rule_evaluations` 表达“不合格条件”：缺耗时、未知 outcome 本身是资格问题；
  无 SQL 时 fingerprint／blacklist 未评估，无开始时 exclusion_interval／window 未评估。
  模板示例无法可靠归一化立即拒绝，绝不回退文本匹配。
- 当前规则 `training-decision/1`。判定逻辑升级后旧快照只承诺已保存计数；
  函数拒绝不支持的判定版本，不能静默拿新代码解释旧版本。②诊断输出计数，
  构建计数的持久保存由③／④完成。归一化或模板变更本身会生成新的原文缓存版本，
  原快照仍引用原缓存。

诊断为多维汇总只推导一次，在事务内 TEMP 表暂存所需列，事务结束删除；
不会在每次构建中永久保存 Decision。全量测量同时记录这一步耗时与全部汇总耗时。
CLI 对模板／时段名称和集群定位也输出摘要，分组只输出不透明 ID，不输出 SQL、数据库名、用户名。

## 别名升级验证与成本

Issue #23 明确要求 55 文件完整重导，核对单条／整批执行级变化；词法出现数或仅原文差分
不能替代这一验收。私有 PG17 内同时准备冻结 v2 与 v3 原文结果，以原 #21 最终计数为基准，
逐执行比较除类别、黑名单评估、版本引用和由此改变的状态之外的所有 Decision 字段。
验证器仅使用临时比较投影，结束自动删除实例；提交证据只含计数和摘要。
旧快照完整摘要保留由合成回归验证；原文缓存不自动清理，生产恢复方式不变。
完整重导及两版缓存增加本地时间和空间成本；[实测报告](../reports/training-category-aliases-2026-09-30.md)
分别记录新版本准备时间、行载荷字节和两版缓存合计物理大小，不外推生产并发容量。
