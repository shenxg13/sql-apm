另两条 `unsupported_distribution_statement` 输入在同一子句中出现
`DROP TABLE … CREATE TABLE … DISTRIBUTED …`，中间缺少分隔符。本轮核对了实际失败子句，

191个递归异常均来自COPY类别，代表输入包含很长的字符串拼接及CASE表达式。代表定位的

本次固定版本收集完整基线，尚未修复这些深度问题或新增语法适配。

## 方法、资源与复现

[全量工具](../../sql_apm/diagnostics/mpp_full_scan.py)流式读取CSV，保留CSV逻辑记录号、物理行范围、
来源文件及字段。批次不拆作独立输入，常量、对象名和格式均不归一化。SHA-256仅用于精确原文
索引，命中后仍比较原文字节，碰撞时报错；它不是产品结构指纹。

临时SQLite索引在本地忽略目录保存原文、首次定位、每文件／字段的出现次数及每个不同输入
的结果。热缓存按32 MiB预算计费；解析子进程每次只处理一个完整输入，沿用512 KiB、5秒限制，
另设每进程512 MiB地址空间上限，每1,000次请求回收进程。异常／超时不生成分组指纹。

完整读取和建索引耗时139.008秒。开始使用4个解析进程，完成138,941个不同输入后，依据本机
12个CPU与充足内存余量保存进度，改用8个进程处理剩余1,017,680个输入，耗时324.863秒。
第一段进程从启动到调整约329.445秒，包含读取阶段；两段解析合计约515秒。
机器证据中的 `parse_seconds` 是最后一次解析调用的耗时，不能单独称为本次全部耗时。
这些是本次机器上的诊断实测，不构成产品吞吐或资源验收承诺。

读取阶段要求新索引，失败后不使用未完成采集；只有全量来源校验完成的索引才允许进入解析。
解析阶段可继续尚无结果的输入，启动及结束均核对解析代码、环境和来源清单摘要；换规则需要
重新建立验证上下文。临时索引不是产品缓存或日志导入实现。

从仓库根目录复现；完整运行须换一个未存在的本地索引路径，现有索引会被保留：

```bash
PYTHONPATH=var/parser-probe/site-packages .venv/bin/python \
  -m sql_apm.diagnostics.mpp_full_scan \
  --database var/parser-probe/full-scan-rerun.sqlite --workers 8 \
  --output var/parser-probe/full-scan-rerun.json

PYTHONPATH=var/parser-probe/site-packages .venv/bin/python \
  -m sql_apm.diagnostics.mpp_full_audit \
  --baseline var/parser-probe/layout-original-replay.json \
  --baseline var/parser-probe/layout-expanded-replay.json \
  --baseline var/parser-probe/layout-broad-replay.json \
  --output var/parser-probe/full-audit-rerun.json
```

第二条默认核对本次 `var/parser-probe/full-scan.sqlite`；核对新索引时显式加上 `--database`。
`--baseline` 是可选的历史诊断结果，缺少本地历史文件时可仅执行失败特征汇总，不能声称旧样本
对照已执行。全量工具的 `--phase parse` 继续未处理输入，`--phase report` 仅重建汇总，
两者均要求同一完整索引及固定上下文。
