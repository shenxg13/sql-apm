## 范围变更与整改

- [范围确认](https://github.com/shenxg13/sql-apm/issues/25#issuecomment-5914482826)：移除物理 sufficiency JSONB 及三个 CHECK；
  SQL 函数按 Build 的封存 ConfigSnapshot 的 thresholds／statistics_version 和统计行派生全部 ThresholdResult。
  默认门槛、17 项指标、metric_null_reasons 和覆盖表语义保持不变；结构仍为未发布的 1.4.0。
- [R1 台账](https://github.com/shenxg13/sql-apm/pull/26#issuecomment-5913073045)的 R1-F001：
  started_at、ID 前缀及分区月份统一由数据库时钟生成；客户端领先 90 秒和 40 天时，
  小型成功为 calculated／true，立即计算失败为 failed／false 并有 statistics_calculation_failed，
  起止时间及月份断言通过；原有 D1 故障用例全部保留。
- R1-F002：统计、版本、计时和训练主题改为③已实现，④发布及展示仍待交付；
  有界同类扫描同步操作入口及导入主题的统计构建状态，保留自动标签、activity 与任务编排边界。
- 非阻塞观察 O2：补充首次新月 DDL 与普通读写等待的真实成本，未扩展运行时锁设计；O3 两处文字错误已修复。
- SQL 推导由独立 Python oracle 验证五层默认及自定义门槛的数量和覆盖临界值，
  比对全部字段及完整原因；新快照变化不改变历史 Build，未知版本明确拒绝。
