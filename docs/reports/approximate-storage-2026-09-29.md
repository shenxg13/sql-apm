# 近似观察存储 1.2.0 实施验证

本报告对应 [Issue #17](https://github.com/shenxg13/sql-apm/issues/17) 的 D1–D6。
用户于 2026-09-29 确认在日志导入 #18 之前补齐近似存储，观察统计另行处理。
实施基线为 `a567dd1bac2c735e552d3a3a636927ca337c4dac`。本报告记录实施验证，不替代独立评审。

## 结构与字段

[字段字典](../design/offline-data-contract/fields.md#approximateruleapproximateinput-与-approximateresult)
逐项对应 sql-approximate/2。新增 5 张 MPP 表分别保存规则、原字节、结果、证据关联和事件引用；
原字节通过 bytea 保留，近似表示用 ASCII JSON 文本保存，避免 JSONB 拒绝 NUL／非法编码转义。
同一原字节和同一规则、结构失败原因的结果可以复用；真实事件仍逐次保存。

可靠指纹新增拒绝 approx: 的 CHECK；Group／Decision 不引用近似表。available 必须有值和
表示，unavailable／failed 必须有原因且值为空；始终保存结构失败原因和观察用途。
原规则、可靠算法及旧报告保持原样。SQL 和参数不在报告中展示。

## 私有实例验证

Python 3.9.5，PostgreSQL 17.10。执行：

```bash
.venv/bin/python scripts/db/verify.py --pg-bin /usr/pgsql-17/bin
```

通过 86 项存储、56 项外键触发器兼容性、63 项连续迁移、18 项直接升级检查及异常清理。
覆盖新库 1.2.0、1.0.0→1.1.0→1.2.0、1.1.0→1.2.0、相同版本重跑，默认及自定义名称，
现有业务内容、关系 OID／relfilenode、旧约束 OID、版本摘要和首次应用时间保留。
中途 DDL／版本登记故障、锁超时、额外对象、错误摘要和外键触发器漂移均拒绝并回滚。
旧库已有错误 approx: 可靠值时升级拒绝，原行保留，不静默清理。

合成近似测试覆盖三种状态、空输入语义、超限输入、非法 UTF-8／NUL、字段条件、
可靠路径隔离、完整字节复用、同输入不同拒绝原因，以及两个残缺 SQL 事件引用同一结果。
测试写入代码位于 tests/database，仅为验证工具；尚未交付 #18 的产品写入事务。
