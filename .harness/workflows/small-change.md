# Small Change Workflow

Use for local, low-risk changes.

1. Read `.harness/index.md` and `.harness/catalog.md`.
2. Read relevant `.project-wiki/` pages.
3. Use the runtime wiki graph capability or repository fallback exactly as
   described in `.harness/tooling-runtime.md` when related knowledge is unclear.
4. Inspect the immediate code path.
5. Make the smallest compatible change.
6. Keep one main variable changing at a time.
7. Run narrow verification.
8. Update wiki if durable knowledge changed.
