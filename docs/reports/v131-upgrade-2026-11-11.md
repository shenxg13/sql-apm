# v1.3.1 升级与导入采集验证

依据 [Issue #84](https://github.com/shenxg13/sql-apm/issues/84)，基线为 #82 合并提交 `db7d3fd`。
本报告区分开发机、验证机、继承证据和生产验证。原始输出保存在本机忽略目录 `var/issue84/`。

## 开发机与继承证据

升级入口单元测试 11 项、性能工具包单元测试 27 项通过。
只读采集 SQL 在私有 PostgreSQL 17 实例通过回放：时间筛选、空运行、多运行、独立计数、
阶段／天／文件计时、参数注入拒绝和敏感字段排除。原文净增测试区分全库新增与集群引用新增。
项目检查、41 项制包测试、12 项安装测试、随包文档检查及三套数据库验证脚本均通过。
新库的 `stats_reset` 可以为 null，原值保留，不能伪造重置时刻。

不复制全量样本做升级演练。迁移文件和结构脚本按 #82 合并提交核对摘要后，继承
[#82 报告](query-refresh-2026-11-11.md)的 0.624 秒带历史升级、业务内容／物理行位置不变及三个时机一致性为 0。
开发配对 +19.59% 是 measured，生产规模 +19.6%～+21.6% 是 modeled；生产效果另行验收。

## 验证机与手册覆盖

验证机起点为 v1.3.0 候选提交 `46e48c4`，可用空间约 165 GB。
身份对齐完成：143 个文件中 132 个完全相同，只替换约定的 11 个身份／文档文件及验收包，
正式 v1.3.0 清单验证通过，服务状态未变。对齐前后摘要与原文件保留。
迁移失败回滚、正式升级、自检、每日运行与定向补测的实施证据尚在采集中，暂不标记通过。
真实访问地址、主机名、SQL 和凭据不公开。

`resume` 沿用目录恢复夹具；连接错误 STOP 和 failed 单元处理的命令与路径未改，
继承 [#79 同机实测](v130-upgrade-2026-11-03.md#带数据升级与故障演练)。
这些继承不等同于本版重新执行真实安装的完整恢复命令；apply 自动回滚另行演练。
