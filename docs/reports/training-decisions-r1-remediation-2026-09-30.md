## 真实输入有界影响核对（measured）

固定比较基准为 R1 的 `b0cc66a495e27b071d25a171c9f517f095841658`。
[机器可读证据](data/training-decisions-r1-remediation-2026-09-30.json)保存新源码摘要、
旧类别摘要、原始索引／清单摘要及历史报告摘要。

1. 只读复用已完整收集的 55 文件原文索引；先核验其整库 SHA-256 为
   `b50c2e2660dab8c4d22f9c1e90a1640555c4caadcc0ed96589dcc97f46db59b2`。
   索引 `collection_complete=true`，55 份文件的集群、文件名、字节数、SHA-256
   与已发布清单完全相同；每份均有读至 EOF、前后 stat 不变和全文件复核标志。
   本轮不改写或重新采集原始日志。
2. 索引覆盖 **1,497,418** 个去重字段原文，范围大于实际入库原文。
   [导入对账](log-ingestion-2026-09-29.md#全量计数与历史差异measured)已经逐字节摘要核对，
   实际保存的原文在该集合外为 **0**；本轮导入逻辑未改。
3. 只有新增暂缓的解析后参数名可能改变结论。这些名字明文含 `transaction` 或 `session`；
   Unicode 转义名字带 `&`，因此同时保留所有含 `&` 的候选。候选还必须含 ASCII `SET`。
   注释可分隔 token，不能拆开关键词或参数名 token；字符串内的假命中由原识别器排除。
4. 在整个索引上选出 **3,106** 个候选；现行未改动的词法器确认其中 **160** 个能进入
   `SET` 分支。对每个执行旧版／新版及快／慢两条路径完整解析，比较整个类别结果。
   其余原文不能到达这次变更的参数名分支。
5. **变化原文 0**，类别转换和变化字段出现次数均为空。校验索引、筛选和比较合计
   **6.373 秒**。字段出现次数不是执行次数；输出不含真实 SQL、数据库名或用户名。

复验命令（输出路径必须不存在，默认索引位于被忽略的本地目录）：

```bash
.venv/bin/python scripts/db/verify_training_category_delta.py \
  --output var/training/new-category-delta.json
```

本轮直接威胁是事务设置被误排除；只改变产品类别解析后的暂缓名单。
有界比较能覆盖变化分支，并核验共享词法器和 MPP 解析器与旧头字节一致。
无需为这一变化重新支付完整导入约一小时、临时数据库约 37 GB 的成本。
真实输入未出现行为变化不等于缺陷不存在；合成端到端用例明确复现旧错并验证修复。

## 与原 D7 证据的关系

[原判定报告](training-decisions-2026-09-29.md)及其 JSON 均保持字节不变。
原报告记录的产品源码摘要中，只有 `sql_apm/training/categories.py` 变化；
验证源码只有 `scripts/db/verify_training.py` 因新增回归变化。
新增差分脚本、初始化帮助、测试文件的新摘要另记于本报告 JSON。
SQL 判定函数、存储读写、配置、归一化和全量验收脚本均未改。

由本次零类别差异及上述未变调用链可推断：对原输入与同样的配置值，四种状态、原因数量、
类别数量、五类计时及组计数不因本次修复变化。原 **7,424,804** 条记录的实测计数保留。
这项结论属于有界影响分析；本轮没有再次全量重导或重测逐条推导性能。

类别版本改变仍会生成新的 `rule_id` 和整版原文缓存；新建快照也有新的配置身份，
原因引用和完整 Decision 摘要因此不能沿用旧值。原报告的规则 ID、完整行摘要、
66.601／523.652 秒缓存准备及全部推导耗时，仍只描述原实测版本。
本轮合成库验证新快照重复推导一致，并确认旧快照继续使用旧缓存。
