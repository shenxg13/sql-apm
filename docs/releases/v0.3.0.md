# SQL APM v0.3.0 预发布

本版用于完全离线环境中的 SQL 基线检索与每日运行演练，**不用于生产**。
应用版本为 v0.3.0，数据库结构为 1.12.0；只支持全新安装，不提供从 v0.2.0 升级的步骤。
完整安装材料通过内网交付，GitHub 附件只有程序包及其 SHA-256 校验文件。

## 相对 v0.2.0 的变化

- 支持按词、整段和完整 SQL 三种检索，分别适合零散线索、连续片段及比较同结构语句；完整指纹值也可直接查询。
- 随包提供 SQL 检索、SQL 列表、SQL 详情、运行状态四个 Grafana 看板；只读数据库账号和只监听回环的指纹服务分别负责查询与指纹计算。
- 每日运行按齐全标记导入已结束的日期，按构建间隔发布，记录待处理问题；可选 systemd 定时器和 SSH 传输脚本。
- **每日运行默认自动清理过期版本结果，并删除到期的原始日志文件**。结果保留月数默认 2，原始文件保留天数默认 45；分别用 `cleanup.enabled=false` 和 `raw_files.retention_days="off"` 关闭。调小保留月数前先人工预览，接收目录不要混放原始证据的唯一副本。
- 所有占用集群的命令都打开数据库连接存活检查；断开连接后由 PostgreSQL 释放会话锁。定时器默认检查间隔 10 秒，最长运行 12 小时。
- Python 从 3.9.5 升至 3.13.16，PostgreSQL 仍为 17.10；随包解释器独立安装，不替换系统 Python。

## 固定组件与维护

离线包固定 Grafana 13.2.3、Business Forms 6.3.5、Infinity 4.1.1、PostgreSQL 数据源 13.0.4，
文件和摘要来自 `grafana/components.json`。保持插件签名校验，关闭启动自动下载；浏览器和浏览器测试依赖不进入离线包。

Grafana 官方对 13.2 系列的支持截止时间为 **2027-05-18**，每个普通次版本支持 9 个月
（2026-10-11 核对的[官方支持表](https://grafana.com/docs/grafana/latest/upgrade-guide/when-to-upgrade/)）。
离线部署不会自动得到安全修复，组件更新需要后续版本重新制包、验证并交付。
Grafana 默认 HTTP，必须登录；启用 HTTPS 的位置、SQLite 数据备份及密码操作见安装手册。
PostgreSQL 仍由操作者用 pg_ctl 启停，服务器重启后须先启动数据库，再核对定时运行是否成功。

## 验证范围与结果

本版实施方在 Kylin V10 SP2 x86_64 上从用户恢复的初始快照完成离线安装；开发机和目标机的十个随包验收入口、两个集群九任务均通过。
两机最终版本的 6,395,051 行统计按既定跨机规则比对通过，只有两列对数统计存在最大 2e-15 的差异（上限 1e-12），其他字段及 NULL 状态一致。

- 每日真实导入中强制终止后，集群占用在 0.056 秒内释放；接续完成，最终统计与同机人工方式精确一致。
- 到期的 55 份日志副本及标记实际删除，原始证据保留；删除前后统计精确一致。自动清理步骤留下记录，本轮没有可删除的旧结果。
- Grafana 和指纹服务被杀后恢复，真实重启后自动启动；人工启动 PostgreSQL 后，错过的定时任务只补一次。
- 三种检索的命中／未命中、两个集群列表、7 个详情样本及运行状态看板通过真实数据浏览器检查；两个数据库账号和 Grafana 的允许／拒绝访问检查通过。
- 120 九任务期间两个常驻服务均运行，主机内存采样峰值 6,237,630,464 字节，未发生 OOM；资源与操作耗时为 measured，不设性能门槛。

用户第二轮已从初始快照亲自完成安装，并在恢复“第 8 步完成”的快照后完成后续 daily 验收。
实施方补验与用户操作分别保存记录，用户轮的结果如下：

- 从开发机分批拉取首批 39 份、追加 16 份日志，自动生成齐全标记；55 次导入成功、36 个日期批次完成，两集群各发布两版，归一化超时为 0，无待处理问题。
- 定时器先拉取再运行 daily；无新增输入时未重复导入或新增版本。用户未单独执行手工重复运行，这一行为由定时运行及后续删除运行记录证明。
- 删除 55 个日志副本和 36 个标记，源端原件摘要不变，删除前后统计精确一致；模拟源端昨天和指定日期的传输及齐全标记检查通过。
- 三种检索的命中／未命中、SQL 列表与详情比较、运行状态看板由用户亲自确认正常；界面结论为用户确认，不记作实施方本轮自动浏览器检查。

用户把五层 basic／P95／P99 数量门槛设为 15／25／25，人工基准为 30／200／1000；
覆盖条件、其他配置、窗口和截止日相同，6,395,051 行统计及 NULL 状态完全一致。
原严格比较的 `passed=false` 和 `same_configuration_and_window=false` 保留，
用户[明确接受这一限定差异并确认本轮通过](https://github.com/shenxg13/sql-apm/issues/52#issuecomment-6109049165)。
该确认不修改产品默认值、比较器或首轮同配置精确比较要求，不豁免其他配置、输入或统计差异。

各轮安装包与交付候选的 111 个产品文件逐路径摘要一致；文档修订另行检查、重新制包。
结果与边界由 [Issue #52](https://github.com/shenxg13/sql-apm/issues/52) 的验证报告及机器记录追溯。

## 已知边界

目标为 Kylin V10 SP2 x86_64 全新安装；不覆盖生产部署、其他系统／架构、120 三十天首批，
或从旧版带数据升级。120 曾接近演练机内存容量，本轮已单列常驻服务运行时的资源实测；
采样峰值与耗时不构成生产容量或性能承诺。v0.2.0 标签和附件保持原样。
