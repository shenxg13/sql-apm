# 近似指纹实施与旧失败重放（2026-09-27）

用户确认观察用近似指纹并明确不补取完整 SQL，随后要求实施并重新验证此前失败输入。
本轮先同步 [Issue #9](https://github.com/shenxg13/sql-apm/issues/9) 的实施及重放范围，
交付 `sql-approximate/1`；正常结构归一化引擎、统计服务与持久化尚未交付。

## 实现与边界

[核心模块](../../sql_apm/sql/approximate.py)只用已取得的文本，生成有类型、版本及规则摘要的
词法表示与 SHA-256。原字节通过 base64 保存，同时保留结构拒绝原因、不完整／不确定
标记、近似诊断和 observation_only。近似成功不能改变原解析失败或填入正常结构指纹。

只替换明确的简单 WHERE 直接比较／IN 列表及 UPDATE 直接 SET 业务值；函数整体、类型
转换、未知表达式、配置与取数数量等保持保守。未闭合、编码或词法歧义处保留剩余原片段。
不猜补语法、重新取得完整 SQL、恢复绑定值或执行 SQL。临近交付的补充用例发现函数内
子查询、括号整体类型转换也需保护；修正后重跑专项并再次完成全部旧失败回放。

[薄诊断入口](../../sql_apm/diagnostics/approximate_sql.py)支持文本／文件；已有 MPP
解析器成功时不生成近似结果，也不冒称已交付正式结构指纹。接口、第一版未替换位置、
命令退出码及资源边界见[接口说明](../design/sql-approximate.md)。

## 完整重放结果

[重放工具](../../sql_apm/diagnostics/mpp_approximate_replay.py)只读复用版本4的原文库及
版本5的完整结果库，重放版本4全部9,293个失败，包含当前8,909个拒绝及384个恢复对照。
旧库开始／结束摘要相同；每条原文字节 SHA、原解析状态／原因均复核。

173个不可用结果均为 `no_sql_tokens`：145个没有实际语句节点，另28个没有在确定边界内
取得可识别的 SQL 命令 token。后者包括22个未闭合注释、5个语法拒绝和1个扫描拒绝，
没有为了提高覆盖而猜测不可识别内容。

8,736个可用输入产生7,762个近似观察分组，124组含多个不同原文；其中2,100个输入实际
替换了业务值，其余仍可按词法表示形成观察身份。这些数字不是可靠结构覆盖率、SQL
等价性证明或分组准确率，不能用来恢复正常基线训练资格。

按原日志输入出现次数，近似可用36,717次、不可用121,076次，两者合计157,793次；
384个恢复对照另出现2,190次。出现次数包含不同日志阶段及重复记录，不是独立执行数。
本轮没有计算生产耗时分布或实施观察统计。

## 证据及验证

[机器证据](data/mpp-approximate-replay-2026-09-27.json)保存全部覆盖分母、逐原因结果、
前后索引摘要、源码摘要、有限代表定位及每个对照结果类别。详细逐条结果保存在本地忽略的
`var/parser-probe/approximate-replay-verified.sqlite`，不复制原 SQL；原文仍由只读基准库保留。
对外报告不导出原文、对象名、字面值、原始字节或 token 内容。

最终重放使用4个持久隔离进程，输入512 KiB、每条5秒、每进程512 MiB；实测
12.223秒，不构成产品吞吐或容量承诺。原 MPP 解析核心与版本5报告中的源码摘要一致，
本轮未重新解析全部成功语料；384个恢复对照和既有解析专项提供本次回归证据。

43项普通测试、81项解析／诊断专项通过；新增12项纯近似测试、7项接口集成和3项重放测试。
覆盖应合并／应区分、Hint／批次、未闭合边界、非法字节保留、保护子树、无可用输入、
资源限制、失败不降级、跨进程稳定性、CLI退出码及报告不泄露输入；最终补强后重新运行
43项普通测试和10项近似集成／重放测试。Python 3.9.5、pglast 7.18 已核对；完整离线
Harness、Markdown／链接及工作区／索引差异检查通过，最终源码摘要与重放证据一致，
原始需求字节未变。验证命令见上述接口说明；不把近似可用称为整个 Issue #9 的验收完成。
