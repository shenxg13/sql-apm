# 统计指标、训练窗口与样本门槛

## Summary

整体、逐天、逐周、跨周星期、跨天小时五个统计层次保留主要指标；
公式、NULL、零值统一，样本充分性按各层适用规则分别判断。
实现聚合、统计公式、窗口或样本不足判断时阅读。

### 各统计层次统一的主要指标清单

下述五个时间统计层次都保留下表中的主要指标，分别使用各自对应的样本集合
计算；不通过平均每日分位数或其他汇总值代替对应样本统计。

| 类别 | 主要统计信息 | 用途 |
| --- | --- | --- |
| 样本覆盖 | 有效训练样本数、活跃天数、训练窗口、首末样本时间 | 说明统计依据及覆盖范围 |
| 耗时分布 | 最小值、最大值、平均值，以及 P25、P50、P75、P90、P95、P99 | 描述典型耗时和不同分位的耗时 |
| 波动程度 | 标准差、变异系数 CV | 描述绝对波动和相对波动 |
| 稳健统计 | MAD、IQR，以及对数耗时的中位数和 MAD | 从受少数极端值影响较小的角度描述分布 |
| 长尾特征 | P95/P50、P99/P50 | 描述较慢执行相对于典型执行的耗时倍数 |
| 样本质量 | 排除执行总数、各原因的排除数量、样本不足提示 | 解释样本筛选和统计依据的局限 |

统计结果随离线基线构建计算并保存至 PostgreSQL，查询时读取已有结果。日常
更新与历史版本保留原则见下述已确认规则；各层保留同一主要指标范围，不要求
每次 activity 比对同时使用全部指标。

样本覆盖按各层实际样本集合解释，具体范围见下述时间统计粒度。逐天有有效
样本时，活跃日期只有该日；按下述逐天试行门槛检查当天数量，不套用整体
窗口的七个活跃日门槛。
保存丰富指标不代表样本已充足，可计算结果仍需保留适用状态；整体和小时画像
采用下述已确认的试行样本门槛。逐周与跨周星期按用户后续要求采用下述新增
试行参数，分别检查单周活跃日与跨周出现次数；其他质量与异常判断条件、
日统计的异常应用条件继续待定。

时间变化统计用于观察分布；后续 activity 采用下述已确认的开始小时优先、
不足时回退同组整体基线的参照选择规则。统计粒度、业务时区及日期／小时归属
采用下述已确认规则；具体展示方式及异常判断规则继续待定。

样本质量统计仅将能可靠识别并归属到相应基线分组及统计时段的执行计入该层；
无法可靠识别或归属的日志问题保留在导入批次层面，不强行分摊。排除总数与
各原因计数采用下述已确认口径；各层分别检查自己的适用样本门槛。

分位数算法、标准差口径、MAD 缩放规则及对数变换采用下述已确认的主要统计
公式；耗时单位、样本不足及无法计算指标的表示按下节已确认规则执行。描述性
统计不直接等同于异常阈值，也不据此自动删除成功但耗时较长的样本；具体异常
判断方法继续另行确认。首期展示指标及样本条件信息，自动“高波动／疑似离群”
标签按[质量展示边界](training-eligibility.md#成功长耗时执行的处理)留待后续确定。

### 已确认的耗时单位与统计空值口径

- 确认日期：2026-09-24。
- 来源：用户对统一使用毫秒并保留小数、区分日志零值与未知耗时、无样本及
  无法计算的指标使用 NULL 并注明原因、样本不足仍保留可计算结果的建议回复
  “确认”。来源状态：current；已确认数值口径，存储与统计功能尚未实现。
- 原始耗时及具有耗时单位的统计指标统一以毫秒存储和计算，保留日志提供的
  小数精度，不取整为整数毫秒；展示可换算成秒或分钟。CV、P95/P50、P99/P50
  等比值无单位，不标作毫秒。此规则用于五类计时和全部已确认的时间统计层次。

| 情况 | 已确认处理 |
| --- | --- |
| 日志明确记录且可靠的 `0 ms` | 保留该记录值；进入统计仍须满足相应样本资格，不把缺失数据补成零 |
| 耗时缺失或不可靠 | 数值为 `NULL`，展示为未知，不补零；已知原因按现有规则记录 |
| 某统计范围没有有效样本 | 有效样本数为 0，均值、分位数等耗时指标为 `NULL`，注明无样本 |
| 指标无法计算，例如分母为零 | 该指标为 `NULL` 并注明原因，例如 P50 为 0 时的 P95/P50，或均值为 0 时的 CV |
| 样本不足但指标可计算 | 保留实际计算数值并标记不足，不仅因未达门槛就置为 `NULL` 或用于自动异常判断 |

- 无有效样本不代表其他已知计数也为零；排除总数及各原因数量继续按实际记录
  统计。日志记录的零值只按所提供的计时值解释，不声称真实耗时精确为零。
- 单个指标无法计算不连带清空其他可计算指标；无样本、未知耗时、无法计算及
  样本不足保持可区分的含义。原因字段、数值类型和是否物理保存空时段记录等
  具体模型仍待实现前落实。
- 此确认不改变整窗没有有效样本时保留当前基线的发布规则，也不改变执行历史
  与训练资格的区别。对数变换及其零值计算、分位数、标准差和 MAD 的定义见下节。

关联条款：[已确认的五类计时统一版本与发布边界](../features/baseline-versions.md#已确认的五类计时统一版本与发布边界)。

### 已确认的主要统计公式

- 确认日期：2026-09-24。
- 来源：用户对连续插值分位数、总体标准差、未缩放 MAD、IQR、固定毫秒单位的
  `ln(1 + x)` 对数统计，以及单样本和无样本处理建议回复“确认”。
- 来源状态：current；公式已确认，统计计算与存储功能尚未实现。
- 五类计时及各时间统计层次分别使用自己的有效样本集合，统一采用
  下表定义。记样本数为 `n`，`x` 为耗时的毫秒数值，`mean` 为算术平均耗时。
  此确认不改变样本资格、分组、时间归属或阶段／调用与完整执行的区别。

| 指标 | 已确认计算口径 |
| --- | --- |
| 最小值、最大值、平均值 | 分别取本范围样本的最小值、最大值及耗时之和除以 `n` |
| P25、P50、P75、P90、P95、P99 | 将样本升序排列，以从 1 开始的位置 `r = 1 + (n - 1) × p` 计算；非整数位置在相邻样本间线性插值 |
| 标准差 | 总体口径：`sqrt(sum((x - mean)^2) / n)`，描述当前样本集合的波动，不使用除以 `n - 1` 的样本标准差 |
| CV | 上述总体标准差除以均值；均值为 0 时按无法计算处理 |
| MAD | `median(abs(x - median(x)))`；不乘 1.4826 或其他缩放系数 |
| IQR | 使用同一分位数算法计算 `P75 - P25` |
| 对数中位数、对数 MAD | 先逐条计算 `y = ln(1 + x)`，再计算 `median(y)` 和 `median(abs(y - median(y)))`，后者同样不缩放 |
| P95/P50、P99/P50 | 使用上述分位数相除；P50 为 0 时按无法计算处理 |

- 分位数采用包含端点的连续线性插值口径（Type 7）。若 `k = floor(r)`，
  小数部分为 `f = r - k`，则非整数位置取 `x[k] + f × (x[k+1] - x[k])`；
  整数位置直接取该样本。P50 同时作为所有中位数计算的定义，偶数个值取中间
  两值的平均；MAD 所需的距离中位数也使用此定义。
- 对数使用自然对数；`x` 固定为毫秒数值，等价于以 1 ms 为参照的
  `ln(1 + duration / 1 ms)`。可靠的零耗时变换为 0；不能改用秒数值却保持
  原公式不变。对数统计无单位，接近零时不等同于 `ln(x)` 或严格倍数变化。
  先变换各样本再求中位数，不以变换原耗时中位数代替。
- 只有一个有效样本时，各分位数等于该值，标准差、MAD、IQR 和对数 MAD
  均为 0；仍标记样本不足，不把零离散度解释为稳定性保证。CV 与分位数比值
  仍按各自分母是否为零处理。
- 没有有效样本时样本数为 0、耗时统计为 NULL；分母为零等无法计算情况为
  NULL 并注明原因，其他可计算指标不受连带影响，沿用上述空值规则。
- 统计定义的确认不确定具体计算库、数据库数值类型或物理空时段记录，也不
  构成异常判定公式。样本门槛、质量判断及实现验证仍分别落实。

定义参考：[PostgreSQL 17 聚合函数](https://www.postgresql.org/docs/17/functions-aggregate.html)、
[Python 3.9 statistics](https://docs.python.org/3.9/library/statistics.html)、
[Python log1p](https://docs.python.org/3.9/library/math.html#math.log1p) 和
[NIST 离散程度](https://www.itl.nist.gov/div898/handbook/eda/section3/eda356.htm)。
这些参考支持定义，不代表已选定或已验证具体实现；首期口径以本次用户确认为准。

### 已确认的排除计数口径

- 确认日期：2026-09-23。
- 来源：用户对“排除总数按执行去重、各原因分别计数，同一次执行在同一原因下
  只计一次；无法可靠识别或归属的问题仍在导入批次统计”的建议回复“确认”。
- 来源状态：current；已确认计数原则，尚未实现执行识别、筛选或统计。
- 在同一基线分组、训练窗口及统计层次对应的范围内，排除执行总数按执行去重，
  同一次执行即使命中多个排除原因，也只计一次。
- 各排除原因分别统计命中的执行次数，同一次执行在同一原因下只计一次。
  同一执行可以分别计入多个原因，因此原因数量之和可能大于排除执行总数。
- 例如，一次执行同时命中 SQL 黑名单与故障时段，排除总数记 1，两项原因各记 1。
- 统计单位沿用单条 SQL／整批请求的已确认规则；真实重复执行仍分别计数，
  不按 SQL 文本或结构指纹把不同执行合并。
- 仅将能可靠识别并归属到相应分组及统计时段的执行计入该层；无法可靠识别
  或归属的日志问题仍在导入批次层面统计，不强行分摊为执行排除数量。

关联条款：[已确认的训练样本基本资格](training-eligibility.md#已确认的训练样本基本资格)。

### 已确认的时间统计粒度

- 确认日期：2026-09-23（原三层统计）；2026-09-25（扩展为五层，确认自然周边界及窗口边缘处理）。
- 历史来源：用户对“整体统计、按天统计、跨天小时画像”三层方案及首期不额外
  保存逐日逐小时汇总的建议回复“确认”。
- 用户随后在明确“跨天小时画像”和“逐日逐小时统计”的区别后，引用前者并
  要求“首期先只保留这个”。按该轮两种小时方式的比较范围，理解为小时维度
  仅保留跨天画像；不将该回复扩展为取消此前确认的整体统计或按天统计。
- 用户进一步明确归纳为“全部，逐天，跨天逐小时”，并将三个层次保留全部
  主要指标一并核对。这是扩展前的确认历史，不限制后续新增层次。
- 当前来源：2026-09-25 用户明确“整体，逐天，逐周，跨周星期，跨天小时，这几个
  维度我觉得比较合理”，同时选择自然周从“周一 00:00 至下周一 00:00”，窗口
  首尾不足整周时“保留窗口内样本，标明不足整周，不补取窗口外数据”。
- 用户随后询问是否需要增加其他层次，对首期保持五层、其他层次按实际需求
  后续评估的建议回复“好的”（2026-09-25）。
- 来源状态：current；首期五个时间层次及周边界已确认，尚未实现构建或存储。
- 对每个“计算集群＋数据库＋执行用户＋SQL 结构指纹＋计时类别”分组，在本次
  构建的训练窗口内分别保留以下五层统计，继续使用北京时间的推算开始时间归属。

| 统计层次 | 对应样本范围 | 主要观察用途 |
| --- | --- | --- |
| 整体 | 训练窗口内该分组全部符合资格的样本 | 总体耗时分布 |
| 逐天 | 按具体推算开始日期分别汇总 | 每日变化 |
| 逐周 | 按具体推算开始日期所属的自然周分别汇总 | 周与周之间的趋势 |
| 跨周星期 | 合并窗口内所有周一、所有周二，依次至周日，共七个星期分桶 | 星期周期差异 |
| 跨天小时 | 合并窗口内各天相同推算开始小时的样本，共 0～23 点分桶 | 一天内不同时段的差异 |

- 逐周采用北京时间半开区间 `[周一 00:00, 下周一 00:00)`；恰好下周一零点
  开始的样本归入新一周。不同自然周分别统计，跨周星期则不保留具体周或日期
  作为分桶键。例如窗口内多个周一合并为同一个“周一画像”。
- 逐周仅使用该自然周与本次训练窗口交集内的样本。窗口首尾不足整周的部分
  仍保留，标明不足整周及实际覆盖；不补取窗口外数据，也不按比例补造样本。
  窗口覆盖完整一周不等于七天均有日志或有效样本，实际样本覆盖仍分别记录。
- 默认训练窗口继续为可调整的 30 个自然日，截止日规则不变；新增逐周统计
  不将训练窗口改为整周倍数或固定滚动七天。窗口不足时沿用实际覆盖说明。
- 各层直接汇总自己的有效样本，不平均每日／每周的分位数。它们是并列的统计
  层次，不把日期、自然周、星期和小时全部叠加为同一个 GROUP BY；首期仍不额外
  持久化“每个日期 × 每个小时”。首期范围保持上述五层；“星期 × 小时”、
  业务日历画像（如工作日、节假日、月末结算期）及逐月统计留作后续候选，
  结合实际样本覆盖、分布差异和业务周期再评估，具体纳入范围另行确认。
- 例如将各天 09:00–10:00 开始的有效样本汇入“9 点画像”。单条 SQL、整批请求、
  阶段和调用继续使用各自已确认的样本单位；跨日、跨周或跨小时执行保留完整
  耗时，按推算开始时间归入对应日期、自然周、星期和小时，不沿执行区间拆样本。

### 暂定的逐周与跨周星期样本门槛

- 暂定及确认日期：2026-09-25。
- 来源：在解释新增两层可先展示统计、充分性门槛另定后，用户明确要求
  “也先给这两个指标暂定一个试行门槛”。随后对下表中的样本数、逐周三个活跃日、

- 来源状态：current；用户已确认采用这组可调整的首版试行参数，尚未经生产
  数据校准，统计与门槛判断尚未实现；后续用实际数据评估并调整。此前“首期
  仅观察、暂不设门槛”的建议不再作为待确认方案。
- 数量条件沿用既有基础／P95／P99 的 30／200／1,000 个有效样本；覆盖条件按
  这两层的样本范围分别设置。下表每格的数量和覆盖要求必须同时满足。

| 条件 | 逐周统计：该具体自然周与训练窗口的交集 | 跨周星期画像：该星期几在训练窗口内的样本 |
| --- | --- | --- |
| 基础样本条件 | 至少 30 个有效样本，且至少 3 个活跃日 | 至少 30 个有效样本，且至少 4 个不同自然周有该星期几的有效样本 |
| P95 样本条件 | 至少 200 个有效样本，且至少 3 个活跃日 | 至少 200 个有效样本，且至少 4 个不同自然周有该星期几的有效样本 |
| P99 样本条件 | 至少 1,000 个有效样本，且至少 3 个活跃日 | 至少 1,000 个有效样本，且至少 4 个不同自然周有该星期几的有效样本 |

- 逐周的活跃日按该周内、位于训练窗口内的有效样本推算开始日期去重计数，
  使用北京时间。某一天执行很多次仍只算一个活跃日，不借用其他周的天数。
  暂取三天是避免仅一次单日集中执行就被标为达到单周覆盖条件，并非完整周
  代表性或统计稳定性的保证；每周只在一天执行的任务仍保留统计并标记覆盖不足。
- 跨周星期按该画像内样本所在的不同自然周计数；例如“周一画像”需要至少
  四个不同周的周一有有效样本，等价于四个不同的有效周一日期。无需四周连续，
  但都必须在当前训练窗口内；不能借用其他星期几、仅有日志而无有效样本的周，
  或窗口外的历史补足。自然周仍按北京时间周一至下周一划分。
- 四次周内相同位置的覆盖用于初步观察重复出现的星期特征，与默认 30 天窗口
  可包含同一星期几四至五次相容。单个周一无论有多少调用也只贡献一个周；
  反过来，四周各一次执行虽满足周数要求，合计四个样本仍不满足基础数量要求。
- 窗口首尾不足整周仍计算并保留统计，使用实际样本检查门槛，不降低门槛、
  不补取窗口外数据。至少三天且数量足够的边缘周可以满足相应样本条件，
  同时继续标为不足整周；样本条件和整周覆盖是两个独立事实。
- 对五类计时均按每个“计算集群＋数据库＋执行用户＋SQL 结构指纹＋计时类别”
  分组独立应用。每个具体周、每个星期画像分别核对；不借用其他分组、计时
  类别或时间层次的样本数和覆盖。请求整体以有效请求为样本，其他类别以各自
  有效阶段／调用为样本，不合并不同单位，也不把调用数算成完整执行次数。
- 基础、P95、P99 条件分别标记。未达到相应门槛仍保存全部可计算指标、实际
  样本数与覆盖，并显示不足原因；不把未达标统计用于自动异常判断。达到门槛
  仅表示符合试行数量与覆盖条件，不等同于可靠性、统计置信度或稳定性已经验证。
- 两层参数分别可调整；窗口缩短导致无法覆盖四个周一等情况时，如实标记不足，
  不自动降低要求。后续根据实际数据评估覆盖集中、分布变化及低频任务等情况。
  异常判定公式与 activity 是否选择这两层作为参照仍按后续阶段另行确认；
  整体／跨天小时原门槛、逐天规则及五类计时的语义边界保持适用。
- 门槛用于标记统计样本条件，不据此删除本来合格的训练样本，也不单独阻止
  基线发布；计算、保存和其他发布检查继续适用，整窗五类均无有效样本时仍保留旧版本。

设计参考：[NIST 周期子序列](https://www.itl.nist.gov/div898/handbook/pmc/section4/pmc4431.htm)
介绍将多个周期的相同位置放在一起观察；本项目据此区分星期覆盖与单日执行次数。
上述 3 天、4 周及样本数量是本项目试行选择，不是该参考给出的通用最低门槛。
