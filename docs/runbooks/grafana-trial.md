## 环境与打开方式

环境由搭建脚本在开发机上准备，全部内容在 Git 忽略的 `var/` 下。两种数据任选，建议用真实数据查看。

```bash
cd /home/sfmon/code/sql-apm
# 真实数据：使用一份 1.10.0 真实库的私有副本，原地升级到 1.11.0（首次会复制约 57 GB）
.venv/bin/python scripts/grafana/setup_dev.py existing --directory var/issue51/real \
  --pgdata var/issue47-r1-fix/full/pgdata --admin-user apm_test_admin --pg-port 55520 \
  --downloads var/issue51/downloads
# 合成数据：几十秒内从空目录搭好，不含任何真实内容
.venv/bin/python scripts/grafana/setup_dev.py synthetic --directory var/issue51/synthetic \
  --pg-port 55532 --grafana-port 3002 --service-port 3003 --downloads var/issue51/downloads
```

- 脚本可以重复执行，结果相同；结束时打印地址。停止用 `setup_dev.py stop --directory 目录`，
  查看状态用 `status`。开发机重启后重新执行同一条命令即可。
- 在 Windows 的浏览器里打开 `http://127.0.0.1:3000/`（合成数据为 `http://127.0.0.1:3002/`）。
- 两个登录账号：`admin`（管理）和 `viewer`（只用于查看）。密码在目录下的
  `private/admin-password` 和 `private/viewer-password` 里，用 `cat` 查看；脚本不显示密码。
- 登录后的主页是“SQL 检索”。页面右上角的链接可以在“SQL 检索”“SQL 列表”之间切换；
  “SQL 详情”从检索结果或列表的一行点进去。

## 需要你自己准备的内容

- 一个熟悉的表名或关键词，两个会同时出现的词。
- 一段从日志或工具里复制的 SQL 片段（可以跨行，可以带双引号的名字）。
- 一条完整的 SQL；以及把它改一改格式、换几个取值后的另一份。
- 一批用分号隔开的多条语句（其中至少一条库里见过）。

真实数据的时间不是当前时间：集群 `119` 是 2026 年 7 月，集群 `120` 是 2026 年 9 月 13 日至 19 日。
从检索结果或列表进入详情时时间范围会自动设好；直接改时间范围时请选到这两段里。

## 需要你知道的实现选择

下面几点是实施时按契约的意思做的具体选择，请在查看时一并确认；不认可的按范围变更处理。

1. **失败、取消、超时的记录没有计时类别。** 这是库里的事实（这些日志行没有耗时）。详情页在每个计时类别下
   都把它们列出来并计入汇总；列表页的“未成功次数”按 SQL 身份统计；只有失败记录的 SQL 以“无计时类别”显示。
2. **按词或整段进入详情时，身份和时间范围按命中的原文算。** 这样命中的原文一定在时间范围内。
   完整 SQL 按整个结构算。
3. **换行统一为一种写法。** 浏览器里的编辑框对整段文字只保留一种换行，Windows 上会把换行改成 CR LF。
   表单一律按 LF 发送；判断“库里有一字不差的原文”时，CR LF 和 LF 视为相同。按词、整段和结构指纹不受影响。
4. **按词和整段的输入上限是 256 KB**，更长的完整语句用“完整 SQL”（上限 512 KB，与命令行相同）。
5. **插件是三个**：Grafana 13 的安装包不含 PostgreSQL 数据源，已按你确认的范围变更把官方数据源插件加进清单，
   并关闭了启动时的自动下载。
6. **结构 1.11.0 没有新增索引和表。** 实测都在目标之内；按时间范围现算的排行会随累计数据量变慢，数字见实测报告。
7. **只读账号建不了临时表。** 管理员引导时收回了项目库上公共的临时表权限，项目账号不受影响。
8. **数据库和执行用户的筛选下拉框**取自有基线的身份；只出现在无基线记录里的不在下拉框中。
