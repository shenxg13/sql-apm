# 基线构建、版本与发布

## Summary

每个集群以固定输入构建统一版本，成功检查后生效，失败和全窗零样本保留原版本。
实现构建、规则更新、任务串行、失败重试或版本发布时阅读。

以下保留原知识索引各节的用户确认、日期、来源状态、证据限制和待定事项。
这些条款定义目标或事实，不表示相关产品功能已经实现；较早条款中的待定表述
应结合明确链接的后续确认阅读，不能覆盖后续已确认规则。
[知识变更记录](../log.md)用于追溯；涉及 Issue 时以其在线正文和评论核对任务契约。

## Contracts

### 已确认的基线更新与历史版本保留

- 确认日期：2026-09-22；2026-09-23 补充部分／全部样本不足及零有效样本的生效规则；
  2026-09-25 确认五类计时统一版本、空结果边界及按集群独立管理的范围，见下节。
- 来源：用户询问是否在每天批量导入日志时重新构建基线、是否只保留最新基线；
  随后对“每日批次完整导入后构建新版本、检查成功后切换生效、保留当前及历史
  统计版本”的建议回复“确认”。
- 用户随后确认：部分 SQL 分组或指标样本不足不阻止新版本生效，不足项目保留
  可计算统计并标记，满足条件的项目正常提供参考；批次完整、构建与发布检查
  通过仍是生效前提，否则继续使用原版本。
- 用户进一步确认：有有效样本但全部分组未达门槛时，其他检查通过后可生效，
  仅展示统计与不足状态；整个训练窗口有效样本为零时，记录空结果及原因，
  不切换版本，保留原版本并显示本次未更新，没有原版本时显示“暂无基线”。
- 来源状态：current；已确认更新与版本保留原则，尚未实现导入、构建或发布流程。
- 每个计算集群当天这一批日志完整导入后，按其选定训练窗口及样本筛选规则
  构建新的基线版本。下述批次完整性、构建、发布及零样本处理均在对应集群内判断。
- 流程为：导入完成 → 筛选训练样本 → 计算新版本 → 检查成功后切换生效。
- 构建失败或检查未通过时，继续使用原来的生效版本，并显示最后更新时间。
- 部分分组或指标未达到样本门槛，不单独构成阻止整个新版本生效的理由；这些
  项目保留可计算统计并明确标记不足，不将未达门槛的项目用于自动异常判断。
  同一新版本中满足使用条件的分组或指标正常提供基线参考。
- 上述规则仍以每日导入批次完整、构建及发布检查通过为前提，不绕过已有的
  文件损坏、导入失败或构建检查失败时阻止新版本生效的规则。
- 整个训练窗口至少一类计时有有效样本，但所有分组都未达到样本门槛时，
  例如初始化前几天，其他检查通过后仍允许新版本生效；保留统计与样本不足
  标记，暂不自动判断异常。
- 整个训练窗口内，五类计时经各自样本筛选后均无有效样本时，记录空结果及
  原因，不切换生效版本；保留原版本并显示本次未更新及最后成功更新时间。
  没有原版本时显示“暂无基线”。零样本结论针对整个选定训练窗口及五类计时，
  不按当天新导入量判断，也不只检查请求整体类别。
- 空结果不覆盖旧版本，也不代表导入必然失败；导入或构建故障仍按各自已确认的
  失败规则处理，不能用零样本状态绕过批次完整性或质量检查。
- 保留当前生效版本和一段历史版本。当前生效版本供日常查询及后续运行中 SQL
  的异常判断；历史版本用于查看基线变化、追溯当时的判断依据。
- 历史版本保存分组统计结果及构建信息，包括训练时间范围、样本数、最终选定的
  统计指标和算法版本等。每次构建还固定并记录指纹算法及函数归一化字典的规则
  版本，变更处理按下节已确认原则执行。主要指标及公式沿用此前已确认口径。
- 执行明细和 SQL 原文不因每次构建新基线版本而重复复制。首期自动清理按
  上述已确认规则暂缓，原始 CSV 由人工管理；具体留存期限及后续清理方案
  在实际入库测量后另行确定。
- 训练窗口采用上述已确认规则。历史基线版本的保留期限尚未确认，后续结合
  分组数量和实际存储量确定。
- 批次完整性采用上述人工确认文件齐全、程序核对清单处理完成的规则；发布
  检查范围采用下述已确认口径。具体检查实现、文件清单格式及任务触发细节
  仍待落实，尚未配置每日自动任务。
  日志获取仍沿用首期手动拷贝、后续每日 SCP 的阶段安排。
- 日常新增日志后的版本更新属于首期范围；此前暂缓的事后补录故障或维护排除
  时段后重算已有基线的流程继续暂缓。

### 已确认的归一化规则版本与更新处理

- 确认日期：2026-09-25。
- 来源：用户对指纹算法与函数归一化字典记录规则版本、每次构建固定规则、
  更新后下次构建在选定训练窗口内统一按新规则生成指纹并计算新基线，以及
  历史基线和原始执行记录保持不变的建议回复“确认”。
- 来源状态：current；已确认规则更新与基线衔接原则，归一化及重建功能尚未实现。
- 为 SQL 指纹算法及函数归一化字典记录规则版本；每次基线构建固定并记录
  所用的一套规则，构建期间不混用不同规则版本。
- 规则更新后，下次构建使用选定训练窗口内已保留、可可靠处理的 SQL 原文，
  统一按新规则生成指纹和归组，再按既有样本资格、五类计时及各时间层次的统计口径
  计算新基线；不能仅让新增日志使用新规则，而把旧规则分组直接混入新版本。
- 仍按计算集群分别构建，满足批次完整、构建与发布检查后才切换生效；新构建
  失败或五类在整窗均无有效样本时，继续按既有规则保留当前版本。规则升级
  不绕过可靠识别、黑名单、排除窗口、样本门槛或其他已确认资格要求。
- 已保留的历史基线保持当时的分组、统计结果及所用规则版本；原始执行／调用
  记录和 SQL 原文保持不变，真实执行不因重新归组而重复计数。每版仍只保存
  相应统计与构建信息，不重复复制执行明细或 SQL 原文。
- 本条要求按新规则生成下一次构建的新版本，不要求自动重算全部历史窗口或
  改写历史版本；因事后补录故障／维护时段而追溯重算的流程继续暂缓。
- 具体版本标识、规则保存方式、原文与各版本指纹的关联、历史版本检索衔接及
  构建性能仍待实施前落实和验证；此处不选定表结构或迁移方案。函数名单及
  逐参数规则继续在既有 Issue 中细化，该 Issue 不扩展为基线重建器的交付任务。

关联条款：[首版函数参数归一化字典的后续维护](../contracts/sql-fingerprints.md#首版函数参数归一化字典的后续维护)；[已确认的 SQL 原文存储方式](../contracts/sql-storage.md#已确认的-sql-原文存储方式)。

### 已确认的构建输入与配置固定

- 确认日期：2026-09-25。
- 来源：用户对每个集群在基线构建开始时固定并记录数据范围和配置、构建期间
  新导入数据及配置变更留待下一次构建、当前版本继续按原输入计算的建议回复
  “确认”。
- 来源状态：current；已确认构建输入边界，固定输入及相关记录功能尚未实现。
- 每个集群在一次构建开始时，固定并记录本次使用的已完成导入批次及数据范围、
  训练窗口、黑名单、故障／维护排除时段、归一化规则版本和样本门槛等配置。
  同一版本的五类计时及全部已确认的时间统计层次使用这套输入和配置。
- 构建开始后新增数据或配置变更留待下一次构建，不改变正在计算的这一版，
  也不因普通新增或配置变化本身自动中止当前构建。首期同集群任务按下节已确认
  规则串行；构建期间新到达的同集群日志由后续任务导入，固定输入原则不表示
  允许再次启动同集群并发导入。
- 后续采用新增数据仍要求相应批次完整、推算开始日期处于该次训练窗口内，
  并满足既有训练资格；不将未完成批次或运行中耗时提前纳入。
- 构建开始时固定的数据范围与训练窗口的历史截止日是两种边界：前者确定本次
  可使用的已导入数据，后者按推算开始日期筛选历史样本。固定输入不改变时间
  归属、样本单位或各类别独立统计原则。
- 当前构建继续接受既有完整性、计算一致性和发布检查；失败或整窗五类均无
  有效样本时，按既有规则保留当前版本。输入固定不豁免发现的问题或发布失败。
- 构建记录保留数据范围、来源及当次配置依据，执行／调用明细和 SQL 原文仍
  复用，不因固定本次输入而要求每版复制。已发布历史结果保持不变，事后补录
  排除时段的追溯重算继续暂缓；本条不新增自动重算或任务触发方式。
- 同集群任务串行及忙时处理按下节已确认原则执行。数据范围与配置的具体标识、
  保存、隔离和调度实现继续待落实，尚未选择数据库快照、锁或表结构方案，
  也未验证构建性能。

关联条款：[首期导入批次的完整性判定](log-ingestion.md#首期导入批次的完整性判定)；[已确认的训练窗口](../contracts/baseline-statistics.md#已确认的训练窗口)；[已确认的黑名单能力与维护分工](../contracts/training-eligibility.md#已确认的黑名单能力与维护分工)；[故障与维护时段的人工排除](../contracts/training-eligibility.md#故障与维护时段的人工排除)；[已确认的阶段与调用样本门槛](../contracts/baseline-statistics.md#已确认的阶段与调用样本门槛)。

### 已确认的同集群任务串行与忙时处理

- 确认日期：2026-09-25。
- 来源：用户对同一集群的导入、构建和发布任务串行执行，已有任务运行时新的
  同集群任务提示占用并退出、人工稍后重试且暂不自动排队，不同集群独立处理、
  查询继续使用当前生效版本的建议回复“确认”。
- 来源状态：current；已确认任务运行边界，互斥、任务入口与运行状态功能尚未实现。
- 首期同一计算集群的导入、构建、发布任务串行执行；已有任一此类任务运行时，
  不再启动该集群另一项此类任务，包括分别启动的导入与构建任务。
- 新启动请求发现该集群已有任务运行时，提示“已有任务运行”并退出，由人工
  稍后重试；首期不自动排队。忙时拒绝新启动不打断或接管当前任务，也不将
  当前任务或批次因此标为失败。
- 不同集群按自身任务、输入和发布条件独立处理；不因 119 存在运行中任务，
  就把 120 判为同集群任务冲突。具体资源限制和跨集群并行能力仍待实施验证。
- 查询继续读取当前已生效基线；新版本仍须完整构建并通过既有检查后生效，
  不向查询暴露尚未发布的中间统计。尚无生效版本时沿用“暂无基线”的表示。
- 构建期间新到达的同集群日志留待后续导入任务处理；当前构建的数据和配置
  继续固定。批次完整性、安全导入重试、失败／空结果保留当前版本等规则不变。
- 互斥实现、任务标识与状态记录、异常退出后的占用恢复、具体入口及资源控制
  仍待落实；此处不选定锁、队列或调度组件，不宣称已验证并发行为。

### 已确认的基线计算失败重试范围

- 确认日期：2026-09-25。
- 来源：用户对日志已完整成功导入、仅后续基线计算失败或中断时，复用导入结果、
  人工重新构建选定训练窗口、首期不做统计断点续算，并记录每次输入配置及失败
  记录、沿用原发布与零样本规则的建议回复“确认”。
- 来源状态：current；已确认重试范围，构建与重试功能尚未实现。
- 已完整成功导入且可继续使用的数据保留并复用，不因后续统计计算失败而要求
  重新导入相同日志。此规则仅针对后续基线计算失败或中断，不将失败／未完成
  的导入当作可用的完整批次，也不豁免已发现的导入数据问题。
- 由人工重新发起构建，按明确选定的训练窗口从头计算五类计时的各时间层次统计；
  首期不实现统计计算的断点续算，不从失败构建的半成品继续计算或发布。
- 每次重新构建仍按已确认规则固定并记录本次实际使用的数据范围、训练窗口
  和配置，保留原失败记录；不把一次新构建的输入变化隐藏成旧构建的延续。
- 同集群串行、样本资格、完整性与计算一致性检查、发布及整窗五类零有效样本
  规则继续适用。新构建满足既有生效条件前，查询继续使用当前已生效版本；
  没有当前版本时仍显示暂无基线。
- 导入失败的安全重试及去重要求保持原有边界；此处暂缓的是统计计算断点
  续算，不排除实现导入安全恢复所需的机制。已发布历史版本保持不变，事后
  补录排除时段的追溯重算流程仍暂缓，也不新增自动重试或排队任务。
- 具体重试入口、失败构建标识、未发布中间结果管理及运行耗时仍待实施验证，
  不将本条表述为已具备恢复能力或已完成性能测量。

### 已确认的五类计时统一版本与发布边界

- 确认日期：2026-09-25。
- 来源：用户对同一次构建的五类计时共用训练窗口与版本、至少一类有有效样本
  时可在既有检查通过后发布、五类全无有效样本时保留原版本，以及不以旧统计
  补齐新版本缺失类别的建议回复“确认”。
- 来源状态：current；版本发布规则已确认，构建、存储和发布功能尚未实现。
- 同一次构建的请求整体、Execute 首次、Execute 续取、Parse 和 Bind 使用同一
  训练窗口，作为同一个基线版本统一生效；各类别仍独立计算各时间层次的统计和判断
  适用的样本门槛，不混合分布或累加不同计时单位的样本作为完整执行数量。
  时间层次以[统计契约](../contracts/baseline-statistics.md#已确认的时间统计粒度)
  为准，包含 2026-09-25 新增的逐周与跨周星期；新增层次采用该契约中的试行门槛，
  达标仍不等同于统计稳定性或异常应用规则已经验证。

| 整个训练窗口的有效样本情况 | 已确认的发布处理 |
| --- | --- |
| 至少一类有有效样本，但部分类别、分组或指标样本不足 | 其他检查通过后允许发布，保留可计算统计及不足标记；全部分组均不足时也适用 |
| 只有 Parse／Bind／Execute 调用样本，没有请求整体样本 | 其他检查通过后允许发布，明确显示缺少请求整体基线；不据此判断整条 SQL 的 activity 异常 |
| 五类全部没有有效样本 | 不切换，记录空结果及原因，保留原版本和最后成功更新时间；没有原版本时显示暂无基线 |

- 上述“允许发布”仍要求日志批次完整、构建及发布检查通过；至少一类有样本
  不允许绕过文件导入失败、构建失败或检查失败。样本须满足对应类别的识别、
  SQL 归属和其他既有资格要求，不能仅因日志有 duration 就算有效样本。
- 新版本反映本次训练窗口，缺失的类别显示无样本；不自动复制旧版本的该类
  统计来补齐。旧统计继续保留在历史版本中供选择查看，历史版本留存期限仍待定。
- 本条明确原先“整窗零有效样本”规则的适用范围为五类均无有效样本，而非仅
  请求整体无样本。检查是否存在有效样本不改变各类别的计数单位，不把调用数
  当作完整 SQL 执行数；版本生效也不等于该版本已有可用于整条 SQL 异常判断的基线。
- 同一次构建的范围按下节已确认的计算集群划分；发布检查范围见下述已确认
  规则，具体检查实现与物理发布方式仍待落实。

关联条款：[已确认的阶段与调用样本门槛](../contracts/baseline-statistics.md#已确认的阶段与调用样本门槛)；[已确认的首期留存与自动清理边界](../contracts/sql-storage.md#已确认的首期留存与自动清理边界)。

### 已确认的按集群独立管理基线版本

- 确认日期：2026-09-25。
- 来源：用户对每个计算集群分别管理当前与历史版本、独立完成导入构建发布，
  同一集群内五类统计统一发布，以及查询展示所选集群窗口和更新时间的建议
  回复“确认”。
- 来源状态：current；版本管理范围已确认，导入、构建、发布和查询功能尚未实现。
- 每个计算集群各有自己的当前生效版本及历史版本，按该集群的日志批次、训练
  窗口和检查结果独立推进导入、构建及发布，不要求所有集群共同切换到一个版本。
- 同一集群内各数据库、执行用户、SQL 分组及五类计时随同一次构建统一发布；
  各分组及类别仍按已确认的五项维度分别统计，不合并不同数据库或用户的分布。
- 一个集群导入失败、批次未完整或构建／发布检查不通过时，保留该集群的当前
  版本；不因此阻止其他集群在自身批次完整且检查通过后更新。例如 119 导入
  失败不阻止 120 正常发布，各自仍遵守既有失败与空结果处理规则。
- 五类全部无有效样本时保留旧版本的规则，也仅在该集群所选训练窗口内判断；
  不能借用其他集群的样本使空结果满足发布条件。
- 查询基线时，展示所选集群及版本的训练窗口和该集群最后更新时间；当前版本
  与历史版本选择按所属集群解释。不同集群的版本日期可以不同，不把其他集群
  的更新当作本集群已更新。
- 集群与日志来源标识采用前述已确认的人工登记和映射规则；版本编号方式、
  来源配置、文件身份、调度及物理存储实现等细节继续落实。

关联条款：[已确认的集群标识与日志来源映射](log-ingestion.md#已确认的集群标识与日志来源映射)。

### 已确认的首期基线发布检查

- 确认日期：2026-09-25。
- 来源：用户对首期采用完整性与计算一致性检查、样本不足及已可靠隔离的问题
  不单独阻止发布，以及暂不增加覆盖率、有效样本比例和相对旧版波动发布阈值
  的建议回复“确认”。
- 来源状态：current；已确认首期发布检查范围，检查与发布功能尚未实现。
- 每个计算集群的新版本在生效前检查：本批次是否完成、是否固定并使用一致的
  规则版本、必需统计结果及构建信息是否完整生成并成功保存，以及样本计数
  和统计结果是否满足既定口径的一致性要求。
- 批次未完成、规则版本混用、必需结果缺失或保存失败、样本计数核对或统计值
  一致性检查失败，均阻止该集群的新版本生效；保留原版本及最后成功更新时间，
  记录失败原因。没有原版本时仍显示暂无基线，其他集群独立处理。
- 计数核对限定在同一基线版本、窗口、SQL 分组及计时类别内：逐天、逐周、
  跨周星期、跨天小时各层的分桶有效样本数之和，分别应等于整体有效样本数。
  逐周按已确认规则保留窗口首尾不足整周的样本，不取窗口外数据；不把多个
  时间层次的数量相加，也不把不同阶段的调用数合并为完整 SQL 执行数。
  按原因排除计数允许一条执行命中多个原因，不能要求原因计数之和等于排除执行总数。
- 统计值检查遵循已确认的公式及空值规则，例如同一有样本范围内的分位数顺序
  与最小／最大值关系应自洽。无样本或指标不可计算时，符合既定规则的 NULL
  及原因不视为结果缺失；合法的零值和样本不足也不作为计算失败。
- 部分或全部分组样本不足，以及问题记录已按规则可靠隔离，本身不单独阻止
  发布；保留可计算统计、已知原因及不足信息。仍须满足其他发布条件，不能
  借此绕过损坏文件、未解决文件冲突、构建或检查失败。
- 整个选定训练窗口内五类均无有效样本时，继续记录空结果及原因，不替换
  当前版本；仅有调用／阶段样本时继续按既有范围展示，不能用作整条 SQL 的
  自动异常判断依据。
- 首期暂不为覆盖率、有效样本比例或相对上一版的指标波动幅度设置额外发布
  阈值，后续结合实际数据再讨论。已有样本门槛与计时覆盖范围保持不变；通过
  发布检查不等于确认统计稳定性或自动异常判定规则。
- 具体核对方法、数值容差、检查报告格式和实现仍待落实及验证；本次不运行
  产品验收，不把日志源码位置覆盖率当作训练质量或已实现检查的证据。
