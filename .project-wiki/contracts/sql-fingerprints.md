# SQL 结构指纹与归一化

## Summary

已确认的常量、参数、对象名、配置值与注释规则统一用于导入和 SQL 检索。
实现指纹、函数字典或 SQL 输入检索匹配时阅读。

适用范围：以下为首期 HashData 契约；设计后续来源接入时，参照
[多类型系统接入约束](../decisions/project-scope.md#已确认的多类型系统接入扩展约束)。

## Contracts

### 首期 schema / search_path 处理边界

- 确认日期：2026-09-22。
- 来源：用户对“保持现有四维分组、保留显式 schema 和表名、不推断隐含 schema、
  暂不还原复杂会话状态，并接受可能混入同一基线的限制”的建议回复“确认”。
- 来源状态：current；这是已确认的首期处理边界，尚未实现指纹或会话处理逻辑。
- SQL 中显式写出的 schema 和表名保留在结构指纹中，用于区分不同的显式对象引用。
- 对未写 schema 的对象引用，不猜测或补全其归属；首期不通过完整重建
  `search_path` 等会话状态来还原实际访问对象。
- 已知限制：在计算集群、数据库、执行用户及 SQL 结构指纹相同时，因隐含 schema
  差异而实际访问不同表的执行可能被归入同一基线。
- 现场是否存在这类用法尚未核实；首期按上述边界处理，不以完成该调查作为前置条件。

技术背景参考：[Greenplum CSV 日志字段](https://knowledge.broadcom.com/external/article/296967/how-to-load-greenplum-pg_log-into-a-tabl.html)
及 [PostgreSQL 9.4 search_path 规则](https://www.postgresql.org/docs/9.4/runtime-config-client.html)。
这些文档支持日志与对象解析的能力边界，不代表已经验证现网的全部会话行为。

关联条款：[已确认的基线分组维度](timing-and-grouping.md#已确认的基线分组维度)。

### 已确认的首期绑定参数处理边界

- 确认日期：2026-09-23。
- 来源：用户对“首期保留 SQL 中的 `$1`、`$2` 等占位符，暂不还原实际绑定参数，
  用完成记录中的 SQL 文本生成结构指纹、用 `duration` 建立耗时基线，不以
  `execute` 参数明细的精确关联作为前置条件”的建议回复“确认”。
- 来源状态：current；这是已确认的首期范围，尚未实现指纹、导入或参数处理逻辑。
- 首期使用选定完成记录中的 SQL 文本作为结构指纹输入；源 SQL 保留原有参数
  占位符，派生的归一化表示遵循下述已确认规则。使用该记录的 `duration` 作为
  首期执行耗时，并按已确认方法推算开始时间。
- 首期不从 `execute` 的 `DETAIL` 恢复或代入实际绑定参数，不要求为此将耗时
  记录与参数明细一一配对；参数值未随完成记录提供，不单独构成训练排除原因。
- 参数化 SQL 的文本可能保留占位符，不能将其展示或描述为已经还原实际参数的
  执行语句。WHERE 条件及 INSERT／UPDATE 中已确认范围的业务常量按下述原则
  归一化；原有占位符与业务常量在这些位置的指纹归并已于 2026-09-24 确认，
  具体算法及其他未确认的规范化细节继续落实。
- 完成记录识别、其他必要的执行关联及此前确认的训练资格继续适用；本次不改变
  原始日志或 SQL 文本的留存安排。

关联条款：[已确认的原生参数与业务常量归并](sql-fingerprints.md#已确认的原生参数与业务常量归并)；[已确认的指纹生成失败处理](../features/log-ingestion.md#已确认的指纹生成失败处理)。

### 已确认的业务常量归一化

- 确认日期：2026-09-23（WHERE 业务常量）；2026-09-24（INSERT／UPDATE 业务值）。
- 来源：用户对同一 SQL 或批次中 WHERE 日期、订单号等业务常量的处理，明确
  选择“业务常量归一化，按结构合并”；后续对将 INSERT 写入值、UPDATE 赋值
  中直接作为列值的业务字面常量也纳入归一化，保留结构信息及特殊值的建议回复
  “确认”。
- 来源状态：current；已确认归并原则及其统计边界，尚未实现指纹算法。
- 同一 SQL 或批次结构相同、仅下列已确认位置的显式业务常量不同，首期将这些
  值归一化为占位标记，归入同一个结构指纹；其他基线分组维度仍须相同：
  WHERE 条件中的业务常量，以及 INSERT … VALUES 和 UPDATE … SET 中直接
  作为列值或赋值的业务字面常量，例如数字、字符串。
- 对象名、列名、表达式结构、显式类型转换以及批次语句顺序保留。此确认不等于
  将 SELECT 投影、函数参数等其他语法位置的常量也无条件归一化。
- 例如，两次独立执行 `UPDATE orders SET status = 'paid' WHERE id = 1001;`
  与 `UPDATE orders SET status = 'closed' WHERE id = 1002;` 可生成相同结构
  指纹；实际聚合仍要求集群、数据库、执行用户及计时类别相同。
- 首期接受不同业务参数导致的耗时差异进入同一组统计，不按这些业务常量的
  具体取值再拆分基线。相同指纹不代表所有参数下执行耗时或执行计划相同。
- 此规则只改变指纹归并，不合并真实执行次数，不改变已确认的单条／整批粒度，
  不从日志参数明细还原实参，也不改写原始输入或确定其留存方式。SQL 检索沿用
  已确认的与日志入库相同的归一化规则。
- UPDATE 赋值中的业务数据适用上述归一化；混合批次的 SET 配置值及显式
  LIMIT／OFFSET 数量继续按下述规则保留。其余非函数参数常量按下节已确认的
  保留规则处理，函数参数仍由字典 Issue 单独确定；不能把 SQL 中所有数字或
  字符串都无条件替换。占位标记编码及其他具体规范化细节待落实；原有 `$n`
  参数与业务常量的指纹归并按后文已确认规则执行。

关联条款：[已确认的归一化规则版本与更新处理](../features/baseline-versions.md#已确认的归一化规则版本与更新处理)。

### 已确认的其余非函数参数常量保留规则

- 确认日期：2026-09-25。
- 来源：用户引用“尚未约定的非函数参数常量先保留具体值、分别统计；已确认
  的归一化规则继续适用，函数参数留在字典 Issue 中确定”的建议回复“确认”。
- 来源状态：current；已确认常量归并边界，归一化器尚未实现。
- 除已经明确纳入归一化的位置外，其余非函数参数常量首期保留具体值；其他
  结构相同时，值不同仍生成不同的结构指纹，并按既有分组维度分别统计。
- 例如 `SELECT amount * 0.1 FROM orders;` 与
  `SELECT amount * 0.2 FROM orders;` 分开生成指纹。此前未约定归一化的
  CASE 结果值也保留，不能仅因它们属于数字或字符串就替换成统一占位符。
- WHERE 业务常量、INSERT … VALUES／UPDATE … SET 直接业务值的既有归一化，
  以及 SET 配置值、LIMIT／OFFSET 数量的既有保留规则继续适用。本条不覆盖
  已确认的特殊规则，也不把 `$n` 与字面常量的等价范围扩展到这些保留位置。
- 函数参数不受本条默认保留规则直接裁定；函数名单、逐参数动作、匹配／默认
  行为和嵌套参数规则仍在已有函数字典 Issue 中确定，不能据此宣称全部函数
  参数或未命中字典的参数都已决定保留。
- 日志入库和 SQL 检索复用相同规则；原始 SQL 保持原样，不因指纹处理而改写。
  规则版本及更新后的整窗归组继续沿用已确认安排，具体算法和语法识别留待实施。

关联条款：[首版函数参数归一化字典的后续维护](sql-fingerprints.md#首版函数参数归一化字典的后续维护)；[已确认的归一化规则版本与更新处理](../features/baseline-versions.md#已确认的归一化规则版本与更新处理)。

### 已确认的原生参数与业务常量归并

- 确认日期：2026-09-24。
- 来源：用户对在已确认允许归一化的业务值位置，将原有参数占位符与字面常量
  合并为同一结构指纹，同时保留源 SQL 占位符、对象及表达式结构、显式类型转换
  和特殊值规则的建议回复“确认”。
- 来源状态：current；这是已确认的指纹与检索行为，尚未实现归一化器。
- 在已确认的 WHERE 业务常量位置，以及 INSERT … VALUES／UPDATE … SET
  直接列值或赋值位置，原有 `$1`、`$2` 等参数占位符与业务字面常量使用统一的
  结构指纹表示；其余对象、表达式结构及显式类型转换仍须一致。
- 例如，`SELECT * FROM orders WHERE id = $1;` 与
  `SELECT * FROM orders WHERE id = 1001;` 应生成相同结构指纹。SQL 检索
  复用这一规则，允许用含具体业务值的同结构 SQL 找到参数化 SQL 的分组。
- 源日志和从中取得的源 SQL 保留原有参数占位符，不恢复或代入实际绑定值；
  统一的是派生的指纹表示，不把归一化结果描述为已还原实际参数的执行原文。
  原文入库采用上述另行确认的精确去重及明细引用方式，保留期限仍待定。
- SET 配置值及显式 LIMIT／OFFSET 数量继续保留；不因业务参数归并而将
  `LIMIT $1` 自动等同于 `LIMIT 1001`，也不推断未知参数值。其余未确认的
  语法位置不因本次确认自动纳入归一化范围。
- 五项 GROUP BY 及单条／整批粒度继续适用。即使指纹相同，不同集群、数据库、
  执行用户或计时类别仍分别统计；真实执行样本继续分别保留。
- 具体指纹算法、占位标记编码和其他未确认的规范化细节仍待落实，须满足上述
  已确认的归并行为；不将本次需求确认表述为已经验证实现或实际匹配率。

关联条款：[已确认的执行配置与取数限制](sql-fingerprints.md#已确认的执行配置与取数限制)。

### 已确认的执行配置与取数限制

- 确认日期：2026-09-23。
- 来源：用户对混合批次 SET 配置值及 SQL 显式 LIMIT／OFFSET 数量的处理，
  明确选择“保留这些特殊值，分别统计”。
- 来源状态：current；已确认指纹保留原则，尚未实现。
- 混合批次中的 SET 配置值保留在指纹输入中，不作为普通业务常量替换；其他
  条件相同但配置值不同的批次分别生成指纹并统计。独立 SET 语句仍按黑名单排除。
- 单条 SQL 或批次中显式写出的 LIMIT／OFFSET 数量保留，数量不同则分别
  生成指纹，不纳入业务常量的归一化规则。
- 首期接受因此产生更多基线分组；范围限于 SQL 文本中显式出现的配置和数量，
  不要求还原日志以外的会话配置，也不推断未显式出现的默认值。
- 如果 LIMIT／OFFSET 只含已有 `$n` 占位符，仍沿用不恢复实际绑定参数的边界，
  不声称已比较未知实参。等价文本表示的规范化及具体指纹编码继续待落实。

### 已确认的普通格式与注释处理

- 确认日期：2026-09-23。
- 来源：用户对排版、SQL 关键字大小写及注释的指纹处理，明确选择
  “忽略普通格式和说明性注释”。
- 来源状态：current；已确认归一化原则及例外，尚未实现。
- 不影响 SQL 语义的空格、换行和关键字大小写差异不改变指纹；普通说明性
  注释也不改变指纹。此规则适用于单条 SQL 及批次中的各条语句，批次顺序仍保留。
- 双引号内的对象名保留大小写。关键字归一化不等于对整个 SQL 转小写，也不把
  字符串内部空白视为排版差异；业务常量是否替换仍按上述已确认的语法位置规则。
- 可能影响执行的 Hint 类特殊注释不按普通注释删除，具体识别规则继续待落实；
  本条不构成现网 HashData 已启用或支持任何特定 Hint 扩展的断言。
- 上述处理用于指纹比较，不改写原始日志；SQL 原文按上述另行确认的完整内容
  精确去重保存，不用格式或常量归一化结果替代原文，具体留存期限仍待定。
