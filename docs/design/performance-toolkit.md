# 生产性能检查工具包设计

依据 [Issue #70](https://github.com/shenxg13/sql-apm/issues/70) 的已确认契约实施。
工具位于 `scripts/performance/`，独立于产品安装包；程序、数据库结构及看板保持既有版本。

## 实施顺序

1. 核对正式包，按生产手册重建验证机；在开发机忽略目录重建固定全量样本库。
2. 实现工作目录、版本检查、只读连接、逐项落盘、取消和脱敏边界。
3. 实现规模／健康、主机采样、确定性代表用例；读取已装看板，运行已装命令行代码。
4. 在目标机单独编译同源码、同参数的 auto_explain；实现普通慢项与列表重点分析。
5. 完成合成拒绝／恢复用例、私有实例语句审计、浏览器 SQL 对照和两机全流程。
6. 生成可重复工具包、中文 HTML 手册和验证报告，交用户审阅，再交独立评审。

## 边界与恢复

生产操作分为 sfmon 主体、postgres 系统视图／计划、sfmon 打包三步。所有状态在安装根以外的
工作目录，连接凭据不进入输出。数据库使用只读会话；每条查询串行执行，HTTP 指纹调用也在
数据库连接关闭后执行。采样线程只读取主机信息。中断取消当前查询并关闭连接；已完成部分
保留，重跑按部分替换，打包记录缺失及未完成部分。

本地对照与查询重放资料仅供本机使用；可公开结果通过字段白名单构造，禁止直接导出查询
返回值、原始错误或执行计划文本。计划保留树、关系名及数字，表达式替换为占位符。
打包前扫描全部候选文件与已知敏感值，业务值及动态文本命中即拒绝。用户确认 Q11 后，
仅对 PostgreSQL 17.10 的五个固定统计字段、两个设置名及对应字段清单／摘要引用按位置豁免，
白名单随结果包声明；未知字段、错误位置及同名业务值仍拒绝。归档保留原字段名，扫描副本
只屏蔽核实过的名称，不删除敏感词，也不丢弃字段值。字段清单随结果生成。

默认计时全部用例、每项三次。操作者可通过重复的 `--case-id` 选择子集缩短运行时间，
结果与摘要记录选取数量并标记部分覆盖；无效编号在计时前拒绝。完整验收仍使用全部用例。

## 验证与成本

单元和私有数据库测试覆盖版本不匹配、三个集群、缺少代表类别、超时后继续、活跃任务拒绝、
只读与单连接、每部分中断、重复选择、追加用例、脱敏哨兵及拒绝打包。
浏览器与数据库日志用于核对看板插值及命令实际 SQL，不以模板字符串相似替代一致性。
Q14 的用户审阅与独立评审分开，自动检查不能代替人工确认。

规模验证为 measured：全量样本重建约两小时／75 GB 为契约估算，实测另记报告。
普通查询三轮不清缓存，重点分析单条默认上限十分钟；两者单独记时。
重点分析可能多次扫描事件表，逐条执行且无并发，只在每日运行之外、无人使用时进行。
自动计划有额外测量成本，独立于三轮计时，不将其耗时混入页面估计。
