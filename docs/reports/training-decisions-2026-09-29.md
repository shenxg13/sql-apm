## 耗时与存储（measured）

本次全量导入耗时 **3,639.900 秒**。下表均为同一私有实例的墙钟时间，无预设性能门槛。

| 阶段 | 119 | 120 |
| --- | ---: | ---: |

| 原文级准备／判定秒数 | 66.601 | 523.652 |
| 汇总字段推导秒数（含 TEMP 写入） | 209.232 | 356.058 |
| 汇总总秒数（含分组输出摘要） | 214.898 | 369.386 |
| 完整 Decision 推导与摘要秒数 | 246.795 | 378.572 |
| 相同快照完整重算秒数 | 243.973 | 129.555 |

原文准备耗时包含选择原文、查缓存、首次分类和结果写入；不同集群共用相同原文／规则结果。
汇总投影与完整 Decision 的耗时分别报告：完整查询强制计算所有字段（含原因引用与八项评估），
逐行 SHA-256 后对四个 64 位分片分别求和，并记录行数；两次结果的全部摘要和行数一致。
这种摘要是有界重放证据，不导出或永久保存逐条判定。耗时包含结果序列化、摘要及临时哈希物化，不能解读为纯规则 CPU 成本。
完整推导在同一实例的汇总之后顺序执行，数据缓存可能已预热；这里不声称冷缓存基准或生产并发容量。

## 验证过程中的失败尝试

首次验证在 1.2.0 启动的长驻进程中重导完全部文件（7,424,804 条，3,600.925 秒），随后升级至 1.3.0。
该进程仍缓存升级前的 Python 连接检查，进入新判定时返回 `schema_1_2_0_required`，未产生判定验收结果；临时实例已自动清理。
本报告只采纳随后从当前代码新启动的独立完整重放结果，首次尝试不计为通过。
