# 归一化与结构指纹实施验证（2026-09-27）

本轮按用户“开始实施”交付可靠结构归一化、结构指纹、固定规则快照、文本／文件命令及
有界真实重放。核心在 `sql_apm/sql/normalization.py`，命令和重放在 `sql_apm/diagnostics/`；
没有重新将业务源码放入 scripts，也没有实现数据库读写、日志导入、统计或基线编排。

[接口与支持矩阵](../design/sql-normalization.md)说明版本、归并规则和边界；
[机器证据](data/sql-normalization-2026-09-27.json)保存源码／依赖／输入摘要、规则快照、
来源定位、逐条脱敏结果及代表性核对索引。生产原文、缓存及全量索引保留在本地忽略目录。

## 实现与规则

- `sql-normalization/1` 使用已验证 `mpp-adapter-probe/5` 和 pglast 7.18 的完整 AST，
  显式栈按语法位置替换业务值；函数选择复用字典 1.0.1，未修改字典规则内容。
- WHERE、INSERT 直接 VALUES、UPDATE 直接 SET 及已知函数业务参数支持常量／原生参数
  归并。控制子树、未知函数、受保护转换、特殊函数、NULL／布尔、对象和批次顺序保留。
- 指纹对类型域、完整归一化结构和固定上下文做规范 JSON＋SHA-256；原文摘要仅作来源核验。
  规则内容快照与内容地址一起保留，不能仅拿一个规则版本字符串解释历史结果。
- 解析明确拒绝时调用已有近似能力；可靠值始终为空，原失败原因不变。配置、资源或内部
  异常不回退。近似成功不构成正常基线身份或执行成功。

批次类别可重叠，类别计数不能当输入总数。

## 验证器超时修正与资源证据

首次组合验证把4次解析合计套用5秒单次预算，输入240848触发一次验证器超时；原始输入
53,438字节。分步诊断观察到核心单次约2.7秒，重复与独立 AST 对照也各需约2.7秒；
逐 token 注入长注释还把格式变体放大到269,375字节。该结果保留在本地初次报告，未隐去。

最终验证器用普通空白及一条说明性注释变形，4个隔离进程、512 MiB 地址空间、每条组合
20秒看门狗，并分别核对各阶段5秒预算。总重放16.885秒；各阶段最大值为归一化2.6952秒、
重复2.6893秒、独立结构对照2.6781秒、格式4.0624秒。最终无预算失败，源库、缓存与源码
摘要在重放前后相同。上述数字是该固定样本和验证组合的测量，不外推全量吞吐或生产容量。

核心 API 本身不做进程隔离，后续批量导入须提供资源控制；相同输入及规则可重试，本模块
没有持久化缓存、任务恢复或并发编排。

## 限制与交付状态

支持矩阵沿用已验证解析能力；复杂 MPP 分区等已有拒绝边界仍在，不声称覆盖全部方言。

重载及受保护子树也可能导致漏合并。没有恢复隐含 schema、会话状态或实际绑定值。

本地模块、文档和验证已交付；PR 提交、在线 PR 契约检查、独立评审和合并另行记录，
